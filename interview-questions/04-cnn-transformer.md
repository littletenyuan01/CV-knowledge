# A. CNN 基础

## Q1. 卷积的计算量与参数量怎么算？为什么 3×3 堆叠比 5×5 好？★★☆ 高频

**参考答案**

**参数量**：`(k × k × C_in + 1) × C_out`（+1 是 bias）。
**计算量（FLOPs，乘加各算一次则为 2×）**：`H_out × W_out × C_out × (k × k × C_in)`。

以 3×3、`C_in = C_out = 64`、输出 `56×56` 为例：
- 参数：`3·3·64·64 = 36,864`
- 乘加：`56·56·64·9·64 ≈ 115.6 M`

**3×3 堆叠优于 5×5 的原因**（VGG 的核心论据）：

```text
两个 3×3 串联的等效感受野 = 5×5，但：
  参数量：2 × (3·3·C²) = 18C²   vs   25C²      → 少 28%
  非线性：2 次 ReLU             vs   1 次       → 表达力更强
  计算量：也更省（按输出尺寸算）
```

三层 3×3 等效 7×7，参数从 `49C²` 降到 `27C²`，且多两次非线性。**代价**是内存访问次数变多（更依赖框架/硬件的融合能力）。

**追问**：*感受野怎么计算？* 递推式：`RF_out = RF_in + (k − 1) × jump`，`jump_out = jump_in × stride`（`jump` 是相邻输出点在输入上的间距，初始 1）。所以**堆叠的 stride 会放大感受野**。

**出处**：Simonyan & Zisserman, *Very Deep Convolutional Networks*, ICLR 2015（VGG）。

## Q2. 1×1 卷积有什么用？为什么它不"卷"？★★★ 高频

**参考答案**

1×1 卷积**只在通道维做线性组合**，没有空间邻域，本质是"每个像素独立的一次全连接"：

```text
输入 (H, W, C_in) ──1×1 conv(C_out)──► (H, W, C_out)
每个像素：y[o] = Σ_i W[o,i] · x[i] + b[o]     ← 逐像素的矩阵乘
```

**四个作用**：

1. **升降维**：降维（bottleneck，ResNet 里 `256→64→256`）能省大量计算。
2. **跨通道信息融合**：把通道当作特征，做线性重组。
3. **替代全连接**：把 `(C,H,W)` 的 GAP 输出接 1×1 conv 等价于 FC，但**与空间尺寸无关**。
4. **改变通道数而不动空间分辨率**：检测头、FPN 侧输出常用。

**为什么它不算"卷积"**：卷积的核心是空间邻域的局部连接 + 权重共享；1×1 核的邻域只有 1 个点，所以它退化成"通道间的全连接 + 空间上共享权重"。

**追问**

- *1×1 conv 和 `nn.Linear` 的区别？* 数学上等价，但 1×1 conv 保留 `(B,C,H,W)` 布局、对 H/W 无限制，实现上更适配 GPU 的 NHWC 张量核。
- *MobileNet 的瓶颈在哪？* 3×3 depthwise（`9·C`）+ 1×1 pointwise（`C·C'`），总计算约是普通卷积的 `1/C' + 1/9`。所以 **1×1 成了主要开销**——这就是 MobileNetV2 用"倒残差"（先升维再 depthwise）的原因。

## Q3. 深度可分离卷积为什么能省这么多？代价是什么？★★☆

**参考答案**

把标准卷积拆成两步：

```text
标准卷积 k×k：        计算 = k² · C_in · C_out · H · W

深度可分离：
  ① depthwise  k×k：  每个通道独立卷积  = k² · C_in · H · W
  ② pointwise  1×1：  通道混合          = C_in · C_out · H · W
                       合计 = (k² + C_out) · C_in · H · W

压缩比 = k²·C_out / (k² + C_out) ≈ 1/C_out + 1/k²
   k=3, C_out=256 → 约 1/8.5
```

**代价**：

1. **精度略降**：depthwise 各通道独立，**没有跨通道交互**，表达力弱；靠后面的 1×1 补回来。
2. **GPU 利用率低**：depthwise 的 `C_in` 次小卷积并行度差、内存访问密度低（arithmetic intensity 低），**实际加速远小于理论 FLOPs 比**——在手机上快，在 GPU 上可能不如标准卷积。

**追问**：*还有哪些轻量化路线？* 分组卷积（ResNeXt/ShuffleNet，用 channel shuffle 补跨组交互）、通道剪枝、量化（INT8）、NAS。**工业检测里**，小目标/细缺陷场景下轻量骨干往往掉点明显，宁可上大模型 + TensorRT 优化。

## Q4. BatchNorm 到底在做什么？训练和推理的差异？为什么 Transformer 用 LayerNorm？★★★ 高频

**参考答案**

**BN 的公式**（对每个通道，统计维度是 `(N, H, W)`）：

```text
μ_c = mean(x[:, c, :, :])          σ²_c = var(...)
x̂ = (x − μ_c) / sqrt(σ²_c + ε)
y = γ_c · x̂ + β_c                  ← γ, β 是可学习参数
```

- **训练**：用**当前 batch** 的统计量，并更新 `running_mean/var`（`momentum=0.1`）。
- **推理**：用 `running_mean/var`（**固定的**），所以推理结果与 batch 组成无关。

**为什么 Transformer 用 LayerNorm**：

| | BN | LN |
|---|---|---|
| 统计维度 | `(N,H,W)`，**跨样本** | 每个样本的**所有特征维** |
| 依赖 batch | 是（小 batch 崩） | **否** |
| 变长序列 | 难处理 | 天然支持 |
| 推理/训练一致 | 需要 running stats | 完全一致 |

Transformer 的训练常见**小 batch + 变长序列 + 自回归推理**（每步只处理 1 个 token），BN 全都不适应。LN 对每个 token 的 `d` 维特征独立归一化，与 batch 无关，这也是它成为标配的原因。

**追问**

- *为什么 BN 能加速训练？* 让每层输入的分布稳定，允许更大学习率；同时有轻微正则效果（batch 统计的噪声）。
- *`γ` 的作用？* 恢复表达能力——归一化后如果恒等映射最优，网络可以学出 `γ=σ, β=μ`。ResNet 里把最后一个 BN 的 `γ` **零初始化**，让每个残差块初始是恒等映射，是训练深层网络的关键 trick（"零初始化残差"）。
- *BN 的坑？* batch 太小（检测/分割常见 batch=2）：统计噪声大 → 换 GN/LN 或 SyncBN（专题二 Q31）。

**出处**：Ioffe & Szegedy, *Batch Normalization*, ICML 2015；Ba et al., *Layer Normalization*, 2016。

## Q5. 感受野怎么算？空洞卷积解决什么问题？★★☆

**参考答案**

**感受野递推**：

```text
RF_0 = 1,  jump_0 = 1
RF_i = RF_{i-1} + (k_i − 1) × jump_{i-1}
jump_i = jump_{i-1} × stride_i
```

例：`conv3×3(s=1)` → `conv3×3(s=1)` → `pool2×2(s=2)`
`RF: 1 → 3 → 5 → 6`（最后一层 `jump` 变成 2，所以 pooling 的 `(2−1)×2=2`）。

**空洞卷积（dilated / atrous）**：在卷积核元素之间插入 `d−1` 个空洞，**不增加参数和计算**就扩大感受野。

```text
d=1:  █ █ █            RF 3
d=2:  █ ░ █ ░ █        RF 5（核还是 3 个权重）
d=4:  █ ░ ░ ░ █ ░ ░ ░ █  RF 9
```

**解决什么问题**：语义分割需要"**大感受野 + 高分辨率**"。传统做法是堆 stride/池化（分辨率掉了，细节没了），空洞卷积能在**保持 feature map 尺寸**的同时扩大感受野（DeepLab 的核心）。

**副作用：网格效应（gridding）**。连续的 `d=2` 卷积只在稀疏格点上采样，会漏掉中间像素。解法是 **Hybrid Dilated Convolution**：用 `1, 2, 5, 9...` 这种**互质**的膨胀率序列，且最后一层 `d=1`。

**追问**：*DeepLab 的 ASPP 是什么？* 并联多个不同 `d` 的空洞卷积（如 6/12/18）+ 全局池化分支，再融合——**多尺度上下文**。工业检测里小缺陷和大背景需要同时看，ASPP 是常用模块。

## Q6. 池化的作用？Max 和 Average 怎么选？为什么现在流行"去掉池化"？★★☆

**参考答案**

**作用**：降分辨率（省计算、扩感受野）、提供**局部平移不变性**、保留主要响应。

| | Max Pooling | Average Pooling |
|---|---|---|
| 保留 | **最强响应**（纹理/边缘） | 平均强度（整体亮度） |
| 梯度 | 只回传给最大值位置（稀疏） | 均匀回传 |
| 适用 | 分类骨干（要显著特征） | 需要平滑/全局统计（如最后的 GAP） |

**"去掉池化"的两种含义**：

1. **用 stride=2 的卷积代替池化**（ResNet 早期就这么做，现代骨干几乎全是 `conv s=2`）：让下采样**可学习**，且避免 max 的梯度稀疏。
2. **去掉最后的 FC，用 GAP**（Global Average Pooling）：参数量骤降（VGG 的 FC 层占了 1 亿+ 参数），不易过拟合，且**输入尺寸无关**。

```text
VGG16:  conv... → flatten → FC(4096) → FC(4096) → FC(1000)   ← 1.2 亿参数
ResNet: conv... → GAP → FC(1000)                              ← 5 万参数
```

**追问**：*GAP 会丢空间信息吗？* 会——所以检测/分割不能只用 GAP；但**分类**恰恰需要"位置无关"的全局表示。这也是 CNN 分类器对位置不敏感、而 ViT 需要**位置编码**的原因。

## Q7. 残差连接为什么能让深层网络训得动？★★★ 高频

**参考答案**

**要解决的是"退化问题"（degradation）**，不是梯度消失——深层网络的**训练误差反而更高**，说明是优化困难，不是过拟合。

```text
普通块：  y = F(x)
残差块：  y = F(x) + x

如果恒等映射最优，只需把 F 学成 0（而非"学一个恒等变换"）
```

**三个层面的解释**：

1. **优化角度**：让"学恒等"变容易（`F→0` 比让一整摞非线性层学恒等简单得多），深网络至少不比浅网络差。
2. **梯度角度**：`∂L/∂x = ∂L/∂y · (1 + ∂F/∂x)`，那个 **`1`** 提供了一条**梯度高速公路**，即使 `∂F/∂x` 很小，梯度也能无损回传（缓解梯度消失）。
3. **集成角度**（通俗解释）：`n` 个残差块可以看作 `2^n` 条路径的集成，浅层路径不易受深层影响。

**工程细节**（面试加分）：

- **维度不匹配时**用 1×1 卷积做投影（或 stride=2 时用投影下采样）；
- **最后一个 BN 的 γ 初始化为 0**（"零初始化残差"），让块初始为恒等映射，训练更稳；
- **Pre-activation**（BN-ReLU-Conv 顺序，ResNet-v2）在超深网络（1000 层）上更好。

**出处**：He et al., *Deep Residual Learning for Image Recognition*, CVPR 2016；*Identity Mappings in Deep Residual Networks*, ECCV 2016。

## Q8. `conv-BN-ReLU` 的顺序能换吗？推理时能融合成什么？★★☆

**参考答案**

**顺序**：标准是 `Conv → BN → ReLU`。原因：BN 需要在线性输出上做归一化，放在 ReLU 后会把一半的负值信息永久丢弃（ReLU 后 ≥0，均值偏正，归一化再移位会导致信息损失）。

**推理期的算子融合**：BN 是**固定的仿射变换**，可以数学上折进前面的 conv：

```text
y = γ·(Wx + b − μ)/σ + β
  = (γ/σ)·W · x + [γ·(b − μ)/σ + β]
  = W'x + b'

W' = W · γ/σ ,   b' = γ·(b − μ)/σ + β
```

融合后**完全消掉 BN**（少一次访存 + 一次 kernel 启动），这是推理引擎（TensorRT/ONNX Runtime）必做的一步优化。前提：BN 已在 `eval()` 且统计量固定，且 conv 与 BN 之间没有其他算子。

**追问**：*训练时能融合吗？* 不能——训练时 `μ/σ` 每步都在变。*`Conv-BN-ReLU` 能融合成一个算子吗？* 可以（TRT 的 `ConvBnRelu`），但只是省内存访问，数学上不改。

## Q9. 什么是"归纳偏置"？CNN 和 Transformer 在这上面的根本差别？★★★（通向 Transformer 的关键题）

**参考答案**

**归纳偏置（inductive bias）**= 模型结构里**先验假设**的集合，它让模型在数据不足时也能学到合理的东西。

| | CNN | Transformer |
|---|---|---|
| 局部性 | 强（卷积核只看邻域） | 无（全局注意力，每个 token 看所有 token） |
| 平移等变性 | 有（权重共享） | 无（靠数据学，或靠位置编码/相对位置） |
| 层级结构 | 天然（池化/stride 下采样） | 原始 ViT 无（所有层同分辨率） |
| 参数效率 | 高（局部 + 共享） | 低（全局注意力参数多、`O(n²)`） |
| 数据需求 | 小数据也能work | **需要大数据或强增强/蒸馏** |

**这解释了 ViT 的核心结论**：在 ImageNet-1k（130 万图）上，ViT 不如同规模 ResNet；但在 ImageNet-21k / JFT-300M 上预训练后，ViT 反超。**数据不够时，CNN 的归纳偏置是优势；数据够多时，它是限制**。

**工业检测的推论**（结合你的经验）：缺陷样本通常只有几百到几千张，**ViT 从头训必崩**；可行路线是 ① CNN 骨干（ResNet/EfficientNet）+ 检测头；② 用大规模预训练的 ViT/自监督特征做**冻结特征 + 轻量头**；③ 强增强 + 蒸馏。

**出处**：Dosovitskiy et al., *An Image is Worth 16x16 Words*, ICLR 2021。

## Q10. 卷积的平移等变性 vs 平移不变性，区别在哪？★★☆（概念精确题）

**参考答案**

- **等变（equivariance）**：输入平移 `t`，输出也平移 `t`——`f(x+t) = f(x)+t`。**卷积具有平移等变性**（对连续域严格，离散域受 stride/padding 影响有边界效应）。
- **不变（invariance）**：输入平移，输出**不变**——`f(x+t) = f(x)`。**全局池化/分类头**才带来不变性。

```text
卷积        → 等变：特征图跟着平移
GAP + FC    → 不变：不管目标在哪，输出同一个类别
```

**这个区分为什么重要**：

1. 检测任务**需要等变**（目标移动，框也要移动）——所以检测器不能用 GAP 把空间信息压掉。
2. 分类任务**需要不变**——所以最后用 GAP。
3. ViT **既不等变也不不变**（没有卷积的权重共享），位置信息全靠位置编码学——这就是为什么 ViT 在"目标位置变化"的数据增强下更脆弱，也是 Swin 引入**相对位置偏置**和**窗口**的部分动机。

# B. 目标检测演进

## Q11. 目标检测的两条主线怎么划分？各自的优缺点？★★☆ 高频（开场题）

**参考答案**

```text
                 ┌── 两阶段 (two-stage) ── R-CNN → Fast → Faster → Mask/Cascade
目标检测 ────────┤
                 └── 单阶段 (one-stage) ── YOLO → SSD → RetinaNet → YOLOv5/8/11
                                          └── DETR 系列（set prediction，无 NMS）

另一条正交维度：
  anchor-based（Faster/YOLOv5） ── anchor-free（FCOS/CenterNet/YOLOv8/DETR）
  静态标签分配（IoU 阈值）      ── 动态标签分配（ATSS/SimOTA/TAL）
```

| | 两阶段 | 单阶段 |
|---|---|---|
| 流程 | 先出候选区域，再分类+回归 | 一次前向直接出结果 |
| 精度 | 通常更高（尤其小目标） | 稍低但差距已很小 |
| 速度 | 慢（RoI 操作串行） | 快 |
| 部署 | 复杂（RoIAlign 算子） | 简单（纯卷积） |
| 现状 | 高精度场景/研究基线 | **工业落地主流** |

**面试时的加分表述**：两阶段和单阶段的精度差距在 YOLOv4/v5 之后基本被**标签分配 + 损失函数 + 数据增强**抹平了，现在的差距更多来自**骨干和训练策略**，而不是结构范式。

## Q12. R-CNN → Fast R-CNN → Faster R-CNN，每一步解决了什么瓶颈？★★★ 高频

**参考答案**

```text
R-CNN（2014）
  选择性搜索出 ~2000 个候选框 → 每个框 warp 到 227×227 → 每个框单独过 CNN
  ✗ 2000 次 CNN 前向（占 95% 耗时）→ 一张图几十秒
  ✗ 训练分四段（CNN 微调 / SVM / 回归器 / 各自独立），不是端到端
  ✗ 候选框要落盘，几百 GB

Fast R-CNN（2015）
  整图过一次 CNN → 在 feature map 上用 RoI Pooling 抠每个框的特征 → 分类+回归
  ✓ 共享卷积计算（快 ~10 倍）
  ✓ 多任务损失，端到端（除候选框生成）
  ✗ 候选框还是选择性搜索（CPU，2 秒/图）→ 仍是瓶颈

Faster R-CNN（2016）
  用 RPN（Region Proposal Network）替代选择性搜索：在 feature map 上滑窗出 anchor，
  分类"有没有目标"+ 回归偏移，与检测头共享特征
  ✓ 候选框生成也进 GPU，真正端到端
  ✓ 一张图 ~5 FPS（当时）
```

**关键概念辨析**（面试常追问）：

- **RoI Pooling 的量化误差**：把浮点框坐标取整到 feature map 网格 → 位置精度损失。**Mask R-CNN 的 RoIAlign 用双线性插值消除量化**，对小目标和分割至关重要（现在几乎都用 RoIAlign）。
- **anchor 是什么**：在每个位置预设若干不同尺度/长宽比的参考框，网络回归"相对 anchor 的偏移"，把"绝对坐标回归"变成"小偏移回归"，更好学。
- **两阶段为什么准**：候选框经过 RoIAlign 后是**高分辨率、对齐好的特征**；单阶段直接在低分辨率 feature map 上回归。

**追问**：*RPN 的损失怎么算？* 每个 anchor 二分类（前景/背景，按 IoU 阈值分配正负，忽略中间地带）+ 正样本的框回归；采样时正负 1:1。

## Q13. IoU、NMS 怎么实现？NMS 有什么缺陷、怎么改？★★★ 高频（现场写代码）

**参考答案**

```python
def iou(a, b):        # a,b: (N,4) xyxy
    x1 = np.maximum(a[:, None, 0], b[None, :, 0])
    y1 = np.maximum(a[:, None, 1], b[None, :, 1])
    x2 = np.minimum(a[:, None, 2], b[None, :, 2])
    y2 = np.minimum(a[:, None, 3], b[None, :, 3])
    inter = np.clip(x2 - x1, 0, None) * np.clip(y2 - y1, 0, None)
    area_a = (a[:, 2] - a[:, 0]) * (a[:, 3] - a[:, 1])
    area_b = (b[:, 2] - b[:, 0]) * (b[:, 3] - b[:, 1])
    return inter / (area_a[:, None] + area_b[None, :] - inter + 1e-9)

def nms(boxes, scores, thr=0.5):
    order = scores.argsort()[::-1]
    keep = []
    while order.size > 0:
        i = order[0]; keep.append(i)
        if order.size == 1: break
        ious = iou(boxes[i:i+1], boxes[order[1:]])[0]
        order = order[1:][ious <= thr]      # 压掉高 IoU 的
    return keep
```

**NMS 的三个缺陷**：

1. **密集目标**：两个真实目标 IoU 高（并排的人、成堆的零件）会被误删 → **Soft-NMS**（按 IoU 衰减分数而不是直接删）、**Cluster-NMS**。
2. **阈值敏感**：0.5 太严漏检、0.7 太松重框。
3. **串行**：Python 循环慢 → 工程上用 **CUDA NMS**（TRT 的 `EfficientNMS`）或 TorchVision 的 `nms`（C++ 实现）。

**追问**

- *NMS 和 anchor 的对应关系？* 无关，NMS 是纯后处理，与生成方式无关。
- *DETR 为什么不需要 NMS？* 见 Q41（set prediction + 匈牙利匹配，天生不产生重复框）。

## Q14. YOLO 系列：v3/v5/v8/v11 各自的核心改动是什么？★★★ 高频

**参考答案**（按"每一代解决什么问题"记）

| 版本 | 核心改动 | 解决什么 |
|---|---|---|
| **v1** | 整图回归成 S×S 网格，每格出 2 个框 | 端到端单阶段，极快；但定位差、小目标差 |
| **v2** | anchor、BN、多尺度训练、高分辨率分类预训练 | 提升召回与定位 |
| **v3** | **FPN 式三尺度预测**（13/26/52）+ Darknet-53 + 多标签分类 + 更好的 backbone | **小目标**大幅改善，成为工业界经典基线 |
| **v5** | CSPDarknet + **PANet** 特征融合 + **Mosaic/马赛克增强** + AutoAnchor + 工程化（导出/部署极顺）+ 大量 anchor 自动聚类 | **工程可用性**（这才是 v5 真正赢的地方） |
| **v8** | **anchor-free**（解耦头 + 分布焦点损失 DFL）+ **TAL 动态标签分配** + C2f 模块 | 去掉 anchor 超参，COCO 上同速更准；**检测头解耦**（分类/回归分开） |
| **v11** | 骨干改进（C3k2 / 更高效的 CSP）+ SPPF + **C2PSA**（在骨干末端引入轻量自注意力）+ 更干净的训练配方 | 精度-速度再平衡，引入**少量注意力**（从纯 CNN 向 hybrid 靠近） |

**几个必须能解释的点**：

- **为什么解耦头（decoupled head）更准？** 分类关心"是什么"（需要语义、平移不变），回归关心"在哪"（需要位置敏感）；共享一个头会互相冲突。
- **DFL（Distribution Focal Loss）**：把框的回归值建模成"离散分布"（如 16 个 bin 上分类），再求期望 → 回归更稳、对边界模糊更鲁棒。**有 anchor-free + DFL** 是 v8 的标志。
- **TAL（Task-Aligned Assigner）**：正样本分配不只看 IoU，还乘上**分类置信度**（`score = cls^α · iou^β`），让"分类好"和"框准"的 anchor 优先当正样本 → 两个任务对齐。
- **Mosaic 增强**：4 张图拼成 1 张 → 小目标变多、batch 内多样性高、对 BN 友好。**缺点**：拼接线附近会出现不自然的物体截断，小数据/工业场景要慎用（可能学到拼缝）。

**追问**：*v8 的 anchor-free 和 FCOS 的 anchor-free 一样吗？* 思路同为"每点直接回归到边界距离"，但 v8 用 **TAL 分配 + DFL**，FCOS 用 center-ness 分支 + 静态 IoU 分配。可以说"同属 anchor-free，分配策略不同"。

**出处**：Redmon et al. (YOLOv1–v3)；Ultralytics YOLOv5/v8 官方仓库与文档；YOLOv11 技术报告（Ultralytics, 2024）。

## Q15. 标签分配（label assignment）为什么重要？静态和动态的区别？★★★（拉开差距的题）

**参考答案**

**问题**：一张图有几千上万个 anchor/特征点，哪些算"正样本"、哪些算"负样本"？

- **静态分配**（YOLOv3/v5、Faster R-CNN）：按**固定规则**——与 GT 的 IoU > 0.5 为正、< 0.4 为负、中间忽略；或"每个 GT 分配给中心最近的若干点"。
- **动态分配**（ATSS、SimOTA、TAL）：**根据当前预测质量**决定谁当正样本，每个 GT 选 top-k 个"最合适"的预测点。

**为什么重要**：分配决定了"模型在学什么"。静态规则的缺陷——

1. **IoU 阈值对尺度敏感**：小目标的 IoU 天然低，正样本太少 → 小目标学不好。
2. **正负样本极度不平衡**（1:1000+），需要 focal loss 或采样。
3. **一刀切的阈值不是最优**：同一个目标，有的 anchor 天生更"合适"。

**ATSS 的核心洞察**（很漂亮的结论）：**正负样本划分方式**（不是 loss、不是结构）是 anchor-free 与 anchor-based 性能差距的**主要原因**；它为每个 GT 按统计量（IoU 的均值 + 标准差）自适应算阈值，两者持平。

**追问**：*动态分配会不会不稳定？* 会——早期预测噪声大，可能"分配错人"，所以常配 **warmup**（前若干 epoch 用静态分配）或加**去噪/一致性**约束（如 DINO 的 denoising）。

## Q16. 检测的损失函数：分类、回归、IoU 系列怎么选？★★☆

**参考答案**

**分类**：

- **BCE（binary cross-entropy）**：多标签/单阶段的主流（每个 anchor 独立判前景 + 每个类别独立 sigmoid）。
- **Focal Loss**：`−α(1−p)^γ log p`，压制大量易分负样本的贡献（RetinaNet 用它解决 1:1000 不平衡）。
- **CE + softmax**：两阶段分类头常用。

**回归**：

| 损失 | 特点 |
|---|---|
| L1/L2 | 对尺度敏感；L2 对离群点敏感 |
| Smooth L1 | 平衡两者，Faster R-CNN 用 |
| **IoU / GIoU / DIoU / CIoU** | 直接优化 IoU；GIoU 处理不重叠（加最小外接框惩罚），DIoU 加中心点距离，CIoU 再加长宽比 |
| **DFL** | 把回归离散成分布，学"框边界的概率分布"再取期望 |

**为什么 IoU 系列更好**：L1 损失下"损失相同"的两个框可能在 IoU 上差很多（对尺度不敏感）；IoU 是**任务的实际指标**，且对尺度自然归一化。

**组合示例**（YOLOv8）：

```text
loss = λ_box · CIoU/DFL + λ_cls · BCE + λ_dfl · DFL
```

**追问**：*CIoU 的 v 项（长宽比）一定有用吗？* 有争议——一些实验表明去掉长宽比项影响很小，甚至 DIoU 更稳〔有争议，不同论文结论不一致，面试时说明这点即可〕。

## Q17. 小目标检测怎么提升？★★★（工业检测必问）

**参考答案**

按"性价比"排序，每条都要说清**为什么**：

1. **提高输入分辨率 / 减少下采样**：小目标的像素本来就少，`stride=32` 的 feature map 上只剩几个像素。用 `stride=8` 甚至 `stride=4` 的检测头（YOLO 的 P2 层）。
2. **多尺度特征融合（FPN/PAN/BiFPN）**：浅层有细节、深层有语义，融合后小目标才有"可分类的语义"。
3. **切图（tiling / SAHI）**：把大图切成重叠小块分别检测再合并——**工业检测里最有效、最常用**的手段，代价是耗时和边界框合并。
4. **数据层面**：小目标过采样、Mosaic/Copy-Paste（把缺陷复制粘贴到不同背景）、超分预处理。
5. **标签分配**：小目标的 IoU 天然低，静态阈值会饿死它——用 **ATSS/TAL** 自适应，或专门调低小目标的匹配阈值。
6. **损失**：小目标对定位误差更敏感，用 **NWD（归一化 Wasserstein 距离）** 或对尺寸归一化的回归损失。
7. **推理端**：**高分辨率 + 滑窗**，或在 ROI 上做第二次精检（两级：粗定位整图，精检测小区域）。

**注意**：本文中的"小目标"在**工业检测**里往往不是"绝对尺寸小"，而是"相对背景对比度低/面积占比小"——所以**对比度增强（CLAHE）和平场校正**有时比换模型更有效（专题三 Q40）。

## Q18. 工业检测与 COCO 基准的差别在哪？为什么直接套 COCO 配方会失败？★★★（这是你简历的核心差异化）

**参考答案**

| 维度 | COCO | 工业检测 |
|---|---|---|
| 类别数 | 80 | 常 1–10 |
| 目标密度 | 中 | 可能极密集（一排零件）或极稀疏（一张图 1 个缺陷） |
| 类间差异 | 语义差异大（猫/狗） | 差异极小（划痕 vs 污渍 vs 反光） |
| 类内差异 | 大（姿态/光照/遮挡） | **很小**（同一工位、同一光源） |
| 数据量 | 10 万+ | 几百到几千 |
| 评价 | mAP（宽松） | **漏检率/过杀率、P99 延迟** |
| 可重复性 | 无所谓 | **必须**（同图同结果） |
| 缺陷形态 | — | 长条、极细、低对比、半透明 |

**"套 COCO 配方"失败的典型原因**：

1. **强增强把缺陷毁了**：Mosaic 拼缝、大幅旋转/缩放会让"划痕"变成"污渍"，甚至引入**伪缺陷**（拼接线被学成缺陷）。工业场景应该用**物理上可能**的增强（亮度/对比度/轻微模糊/噪声），不要几何乱变。
2. **Anchor 聚类用不上**：COCO 的 anchor 尺寸分布和你的缺陷完全不符，AutoAnchor 必须重跑。
3. **类别不平衡被忽略**：某类缺陷只有 20 张 → 直接用 CE 会全预测成多数类。要 **Focal / 重采样 / 过采样**。
4. **mAP 掩盖了业务问题**：mAP 0.85 看起来好，但漏检的那 15% 可能全是最危险的缺陷 → 必须按**缺陷类型和尺寸切片**评估，并看 **PR 曲线在业务阈值处**的表现。
5. **过拟合到工位**：所有训练图都来自同一台相机同一光照，换台设备就崩 → 训练时**跨设备/跨批次**采样，或做**域增强**（模拟不同色温/曝光/噪声）。

**你该说的那句话**：

> "工业检测的难点不在模型结构，而在**数据闭环和评价指标**。我的做法是先把'漏检率/过杀率'定成验收线，再倒推阈值和模型；训练时只用物理上说得通的增强，并且留一个**按批次切分**的测试集（同批次的图不能同时出现在 train 和 test），否则指标虚高。"

## Q19. 检测模型部署时，哪些层会拖慢速度？怎么优化？★★☆

**参考答案**

**拖慢的环节**（按常见程度）：

1. **NMS**（后处理）：密集目标时几十万个框排序，CPU 上能占一半时间 → 用 **CUDA NMS / TRT EfficientNMS**，或先按分数阈值裁剪。
2. **RoIAlign**（两阶段）：动态 shape、算子碎片 → 单阶段更易部署；必须两阶段时用 TRT 插件。
3. **动态 shape**：变长输入导致 TRT 反复重建/搜索 → 固定几个 shape 做 profile。
4. **预处理在 CPU**：resize + 归一化在 CPU 上很贵（尤其大图）→ 用 GPU 预处理（DALI / TRT 的预处理插件 / cv::cuda）。
5. **FPN 的多尺度输出**：小目标需要高分辨率输出，`stride=4` 的 head 上采样/卷积成本高。
6. **自定义算子**：如 DFL 的 softmax、解耦头里的 split/concat → 尽量让 TRT 能融合。

**回答时的结构**：先说"先 profile 再优化"（nsys/TRT 的逐层耗时），再按"后处理 → 预处理 → 模型内算子"的顺序讲，因为**后处理往往是最大的一块**且最容易被忽略。

## Q20. DETR 系列和 YOLO 系列，工程上怎么选？★★☆

**参考答案**

| | YOLO 系 | DETR 系 |
|---|---|---|
| 部署成熟度 | **极高**（TRT/ONNX/ncnn 全支持，社区大） | 中等（Deformable Attention 需要自定义算子/插件） |
| 后处理 | 需要 NMS（可 CUDA 化） | **无 NMS**（端到端，延迟稳定） |
| 小目标 | 靠 FPN/多尺度，成熟 | 原版 DETR 弱；Deformable/DINO 改善 |
| 训练收敛 | 快（几十 epoch） | 原版极慢（500 epoch）；Deformable 约 50 epoch |
| 密集目标 | NMS 是瓶颈（需调参） | 天生适合（集合预测，不重复） |
| 调参难度 | 中等（anchor/阈值/增强） | 高（query 数、匹配代价权重、学习率 schedule） |

**结论**：**产线优先选 YOLO**（工具链成熟、迭代快、可解释性好）；如果场景是**密集目标**且 NMS 调不明白，或者要做**端到端的集合预测/多任务统一**，才考虑 DETR 系（Deformable DETR / DINO），并接受算子移植的成本。

# C. Attention 与 Transformer

## Q21. 自注意力的公式是什么？为什么要除以 `√d_k`？★★★ 高频（必问）

**参考答案**

```text
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V

Q: (n, d_k)   K: (m, d_k)   V: (m, d_v)
Q·Kᵀ : (n, m)  ← 相似度矩阵，n=m 时是 n×n
```

**为什么除以 `√d_k`**：假设 `q` 和 `k` 的各分量独立、均值 0、方差 1，则点积 `q·k = Σ_{i=1}^{d_k} q_i k_i` 的方差是 **`d_k`**，标准差 `√d_k`。不缩放的话，`d_k` 越大点积越大，softmax 会**饱和**（一个位置接近 1，其余接近 0），**梯度趋近于 0**（softmax 的雅可比在饱和区极小），训练不动。除以 `√d_k` 把方差拉回 1。

```text
d_k=64: 点积标准差 ~8      → softmax 尖锐但可控
d_k=512: 点积标准差 ~22.6   → 不缩放几乎必饱和
```

**追问**

- *为什么是 `√d_k` 而不是 `d_k`？* 要的是把**标准差**归一化，不是方差。
- *softmax 的"温度"是什么？* 温度 `T` 就是这里的缩放因子：`softmax(logits/T)`。`T` 大 → 分布平缓；`T` 小 → 尖锐。这个视角在蒸馏、采样里都用得到。
- *复杂度？* `Q·Kᵀ` 是 `O(n²d)`，`softmax` 是 `O(n²)`，`·V` 是 `O(n²d)`——**`n²` 是 Transformer 显存的根源**（Q49）。

**出处**：Vaswani et al., *Attention Is All You Need*, NeurIPS 2017。

## Q22. 多头注意力（MHA）为什么有效？多头的计算量会增加吗？★★☆

**参考答案**

**做法**：把 `d_model` 拆成 `h` 个头，每头 `d_k = d_model / h`，各自做注意力，再拼接后线性变换。

```text
X (n, 512) ──┬─ W_q1,W_k1,W_v1 → head1 (n, 64) ─┐
             ├─ W_q2,W_k2,W_v2 → head2 (n, 64) ─┤ concat (n, 512) → W_o → (n,512)
             └─ ...                             ─┘   h=8, d_k=64
```

**为什么有效**（几种解释，面试说前两条就够）：

1. **不同子空间的不同关系**：一个头学"相邻位置"、一个学"同类物体"、一个学"语法依赖"——单头只能平均掉这些模式。
2. **集成效应**：多个低维注意力比一个大注意力更稳（类似多专家的集成）。
3. **表达力**：拼接后的 `W_o` 能把不同头的模式重新组合。

**计算量不变**（这是常考的反直觉点）：`h` 个头各用 `d/h` 维，`h × (n² · d/h) = n²d`——**总 FLOPs 与单头（`d` 维）相同**。但**显存/访存**会增加（多头并行、小矩阵乘的 kernel 效率低）。

**追问**：*MQA/GQA 是什么？* MQA（Multi-Query）：所有头共享一份 K/V；GQA（Grouped-Query）：每组头共享 K/V。它们**大幅减少 KV cache 显存**（LLM 推理的关键优化），代价是轻微精度损失。

## Q23. 位置编码：为什么需要？正弦编码的公式和性质？★★★ 高频

**参考答案**

**为什么需要**：自注意力是**置换等变**的——打乱 token 顺序，输出只是跟着打乱，模型**根本不知道谁在前谁在后**。图像里被切成 patch 后同理，所以必须注入位置信息。

```text
自注意力对排列不变：Attention(P·X) = P·Attention(X)
→ 不加位置编码，图像 patch 的顺序对模型无意义
```

**正弦编码**（原始 Transformer）：

```text
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```

**三条性质**（面试常追问）：

1. **唯一性**：每个位置有唯一的编码。
2. **有界**：值域 `[-1, 1]`，不会随位置爆炸。
3. **相对位置可线性表示**：`PE(pos + k)` 可以由 `PE(pos)` 经**线性变换**得到（旋转矩阵），所以模型能学到"相对距离"。

**变体**：

| | 形式 | 特点 |
|---|---|---|
| 正弦（固定） | 上面的公式 | 无需训练，可外推到更长序列（理论上） |
| **可学习** | `nn.Embedding(n, d)` | ViT/BERT 用；受限于训练长度，**不能外推** |
| **相对位置偏置** | 加在 attention logits 上 | Swin/T5 用；只依赖相对距离，长度无关 |
| **RoPE**（旋转位置编码） | 把 q/k 按位置旋转 | LLM 主流（LLaMA），相对位置 + 可外推 |
| **2D 编码** | 行列分别编码再拼接 | 图像专用（ViT 早期、DETR） |

**追问**：*DETR 为什么用 2D 正弦编码？* 图像是二维的，行列各编一份再拼起来（或交错），保证"相邻位置编码相近"，同时支持任意分辨率（公式不依赖 H/W）。

**出处**：Vaswani et al., 2017 §3.5；Su et al., *RoFormer*（RoPE），2021。

## Q24. Transformer 的完整结构：Encoder 和 Decoder 各有什么？★★☆

**参考答案**

```text
Encoder Block × N                          Decoder Block × N
┌──────────────────────────┐              ┌────────────────────────────────┐
│ x = x + SelfAttn(LN(x))  │  Pre-LN       │ x = x + SelfAttn(LN(x))        │ ← 带因果 mask
│ x = x + FFN(LN(x))       │              │ x = x + CrossAttn(LN(x),       │ ← 看 encoder 输出
└──────────────────────────┘              │              enc_out)          │
                                          │ x = x + FFN(LN(x))             │
                                          └────────────────────────────────┘
```

- **Self-Attention**：token 之间互看（encoder 是全看的双向；decoder 是**因果 mask**，只能看左边）。
- **Cross-Attention**：`Q` 来自 decoder，`K/V` 来自 encoder 输出——**这是 DETR 里"query 找图像特征"的地方**。
- **FFN**：两层线性 + 激活，中间维度 `4×d_model`（先升维再降回），逐 token 独立作用。**参数量占整个 block 的 2/3**（`2 × 4d²` vs attention 的 `4d²`）。
- **残差 + LayerNorm**；**Dropout**；**位置编码**加在输入上。

**Pre-LN vs Post-LN**（细节题，答对加分）：

| | 结构 | 特点 |
|---|---|---|
| Post-LN（原始） | `LN(x + Sublayer(x))` | 表达力强，但**必须 warmup**，深层难训 |
| **Pre-LN**（主流） | `x + Sublayer(LN(x))` | 梯度更稳，不需要 warmup，深网络友好 |

**追问**：*FFN 为什么要先升维 4 倍？* 给非线性变换更大的"工作空间"（类似卷积里的瓶颈结构反过来），同时增大容量；有实验表明 `4×` 是个不错的平衡点。

## Q25. 自注意力、交叉注意力、自回归注意力的区别？★★☆

**参考答案**

| | Q 来源 | K/V 来源 | mask | 用途 |
|---|---|---|---|---|
| **Self-Attention** | X | X | 无（双向） | 编码上下文 |
| **Masked Self-Attention** | X | X | **因果 mask** | 自回归生成（GPT） |
| **Cross-Attention** | Y（decoder） | X（encoder） | 无 | 条件生成、DETR 的 query 找特征、多模态 |

```text
因果 mask（下三角）：
   0  -∞  -∞  -∞
   0   0  -∞  -∞        ← softmax 后上三角为 0，保证"看不到未来"
   0   0   0  -∞
   0   0   0   0
```

**为什么需要因果 mask**：自回归训练时，一次前向要预测所有位置；如果不 mask，位置 `t` 会看到 `t+1` 的答案（标签泄漏），训练 loss 很低但推理完全不能用。

**追问**：*DETR 的 decoder 需要因果 mask 吗？* **不需要**——它一次输出全部 100 个框，不是自回归的（DETR 并行解码）。但 DETR 的 decoder 输入是"object queries"（可学习的向量），不是图像特征。

## Q26. Transformer 相比 RNN 的优势？相比 CNN 的优势？★★☆

**参考答案**

**vs RNN**：

1. **并行**：RNN 必须按时间步串行，Transformer 一次算完所有位置 → 训练快。
2. **长程依赖**：RNN 的信息要经过 `n` 步传递，梯度会衰减（长距离依赖学不到）；Transformer 的任意两 token 是**一步直连**（路径长度 1）。
3. 代价：`O(n²)` 复杂度 vs RNN 的 `O(n)`。

**vs CNN**：

1. **全局感受野**（第一层就全局）：CNN 要堆很多层才能"看到"远处的像素。
2. **动态权重**：注意力的权重**由输入决定**（content-based），卷积核是**固定的**（input-independent）——这是更本质的差别。
3. 代价：**丢掉了归纳偏置**（Q9），需要更多数据；`O(n²)` 显存。

**一句话总结**：Transformer 用"**更大的模型容量 + 更少的结构先验**"换取"数据足够时的更高上限"。

## Q27. 为什么 Transformer 训练需要 warmup？★★★（进阶）

**参考答案**

**三条原因**（能说清两条就不错）：

1. **Adam 的二阶矩在训练初期估计不准**：`v_t` 用指数平均估计，前几步样本很少，估计方差大 → 更新步长可能极大，一步就把参数推到坏区域。warmup 让 `v_t` 积累够统计量。
2. **Post-LN 的梯度尺度问题**：深层 Post-LN 结构在初始化时，靠近输出的层梯度大、靠近输入的层梯度小；直接大 lr 会让输出层"先跑"，破坏浅层。warmup 给所有层一个"同步起步"的过程。
3. **注意力分布初期接近均匀**：`Q·Kᵀ` 初始化时接近 0，softmax 输出接近 `1/n` 的平均池化，此时梯度信号弱且方向不稳定。

**常用配方**（原始论文）：

```text
lr(t) = d_model^(-0.5) · min(t^(-0.5), t · warmup^(-1.5))
                                        └── 前 warmup 步线性增长，之后按 1/√t 衰减
```

**追问**：*用 Pre-LN 还需要 warmup 吗？* 理论上可以不用，但实践中短 warmup（几百步）仍然有益，成本几乎为零——所以几乎所有配方都留着。

**出处**：Vaswani et al., 2017；Xiong et al., *On Layer Normalization in the Transformer Architecture*, ICML 2020。

## Q28. 注意力里有哪些"效率优化"？FlashAttention 做了什么？★★★（加分）

**参考答案**

**问题**：标准注意力要**显式物化 `n×n` 的注意力矩阵**（`n=4096` 时 fp16 是 32 MB/头/层），显存和访存都爆炸；而 GPU 的算力其实够——**瓶颈在显存带宽（memory-bound）**。

**FlashAttention**：**分块（tiling）+ 在线 softmax + 不物化中间矩阵**。

```text
标准：  QKᵀ → 写回显存(n²) → softmax → 写回(n²) → 乘 V → 写回
        ↑ 多次 HBM 读写，n² 显存

Flash：把 Q/K/V 切块，逐块算 → 在 SRAM 里用"在线 softmax"（running max/sum）
        增量更新，永远不写 n² 矩阵
        ✓ 显存 O(n)，✓ HBM 访问大幅减少，✓ 结果数值等价（不是近似）
```

**关键点**：它是**精确**算法（不是近似），只是换了计算顺序（数学等价，浮点误差略不同）。加速主要来自**减少 HBM 读写**，通常是 2–4 倍。

**其他路线**：

| 方法 | 思路 | 代价 |
|---|---|---|
| 稀疏/局部注意力 | 只看邻域窗口 | 丢全局 |
| **窗口注意力（Swin）** | 只在窗口内算，窗口间靠 shift 交流 | 需要设计窗口划分 |
| 线性注意力 | 用核函数近似 softmax，`O(n)` | 精度下降 |
| **MQA / GQA** | 共享 K/V，减少 KV cache | 主要优化推理 |
| **KV cache + PagedAttention** | 推理时复用 K/V | 显存管理 |

**追问**：*FlashAttention 能用在检测里吗？* 高分辨率特征图（`stride=4` 时 token 数上万）时收益极大；但窗口注意力（Swin）已经把 `n²` 降到 `n·w²`，两者可以叠加。

**出处**：Dao et al., *FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness*, NeurIPS 2022。

## Q29. 为什么 Transformer 的 FFN 占了大部分参数？这对部署意味着什么？★★☆

**参考答案**

以 `d_model = 768` 为例，一个 block 的参数量：

```text
Attention:  W_q, W_k, W_v, W_o 各 d×d  →  4d²  = 2.36 M
FFN:        d×4d + 4d×d          →  8d²  = 4.72 M
                                              ↑ 是注意力的 2 倍
```

**部署含义**：

1. **剪枝/蒸馏要优先动 FFN**（参数多、但每层作用独立，容易压）。
2. **量化时 FFN 的权重占显存主体**（ViT-B 86M 参数里约 2/3 在 FFN）。
3. **推理延迟**：FFN 是逐 token 的矩阵乘，**batch 大时算力受限、batch 小时访存受限**——这解释了为什么 ViT 在小 batch 下"不划算"。

**追问**：*MoE 是什么思路？* 把 FFN 换成多个专家，每个 token 只激活 top-k 个 → 参数量大但计算量不变（稀疏激活）。LLM 里常见，视觉里也有（V-MoE）。

## Q30. 注意力权重可视化能说明什么？不能说明什么？★★☆（批判性思维题）

**参考答案**

**能说明**：

- 某些头确实聚焦在语义相关的区域（物体边界、同类实例）；
- 模型在"看哪里"——用于**调试**（比如检测漏检时看 query 关注到了背景）。

**不能说明**（这是重点，也是很多论文被批评的地方）：

1. **注意力权重 ≠ 因果贡献**。权重高不代表该位置对输出重要（后面还有 `V` 的投影、残差、多层叠加）。
2. **不能直接当解释**：有多篇工作（如 *Attention is not Explanation*）指出，注意力分布可以被大幅改变而输出几乎不变。
3. **无法反映跨层交互**：第 3 层的注意力被第 10 层"覆盖"了，单独看某一层没意义。

**面试时的正确说法**：注意力图可以作**调试线索**，但不能当**可解释性证据**；要归因得用**梯度类方法**（Grad-CAM）、**遮挡/扰动实验**、或 **integrated gradients**。

**出处**：Jain & Wallace, *Attention is not Explanation*, NAACL 2019；Wiegreffe & Pinter, *Attention is not not Explanation*, EMNLP 2019（两篇对着打，说明这个问题本身有争议）。

## Q31. 为什么 Transformer 用 GELU 而不是 ReLU？★★☆

**参考答案**

GELU：`GELU(x) = x · Φ(x)`（`Φ` 是标准正态的 CDF），常用近似 `0.5x(1 + tanh(√(2/π)(x + 0.044715x³)))`。

**相比 ReLU**：

1. **平滑**：处处可导（ReLU 在 0 处不可导，且负半轴梯度为 0 → 神经元"死亡"）。GELU 在负半轴有小的非零梯度，缓解 dying ReLU。
2. **随机正则的解释**：`x·Φ(x)` 可以理解为"按输入大小做随机门控的期望"——输入越大越可能被保留，是 ReLU 的**平滑随机版本**。
3. 实践中在 Transformer/大模型上通常比 ReLU 高一点精度。

**代价**：`Φ` 的计算比 `max(0,x)` 贵（所以有 tanh 近似、sigmoid 近似 `x·σ(1.702x)`）。

**追问**：*现在还有什么？* **SwiGLU**（`Swish(xW) ⊙ xV`，LLaMA 用），门控结构，通常比 GELU 再好一点，但多一个权重矩阵（所以 FFN 的中间维度常从 `4d` 降到 `8/3 d` 来保持参数量）。

## Q32. 残差在 Transformer 里和 CNN 里作用一样吗？★★☆

**参考答案**

**作用同类但细节不同**：

- **相同**：都给梯度提供"恒等通路"，让深层网络可训；都让"学恒等"变容易。
- **不同**：
  1. CNN 的残差跨的是**卷积层**（局部算子），Transformer 的残差跨的是"**注意力 + FFN**"两个子层，每个子层都有**独立的残差**。
  2. Transformer 的**归一化位置**（Pre/Post-LN）对残差通路的干净程度影响巨大——Post-LN 的残差通路上串了 LN，梯度要穿过 LN；Pre-LN 让残差通路**完全干净**（`x + f(LN(x))`），这是 Pre-LN 更稳的根本原因。
  3. **初始化**：GPT-2 把残差分支的输出投影**按层数缩放**（`1/√(2N)`），防止残差累积导致方差随深度爆炸——Transformer 没有 BN，只能靠初始化 + LN 控制尺度。

**一句话**：**残差解决"深"，LayerNorm 解决"稳"，两者的相对位置决定训练稳定性**。

# D. 视觉 Transformer

## Q33. ViT 是怎么把图像变成序列的？它为什么需要大规模预训练？★★★ 高频

**参考答案**

```text
图像 (H, W, 3)
  → 切成 P×P 的 patch（P=16）：(H/P × W/P) 个 patch，如 224/16 = 14×14 = 196
  → 每个 patch 展平成 3·P² = 768 维向量
  → 线性投影到 d_model=768      ← 等价于 stride=P 的卷积
  → 加 [CLS] token（可学习）
  → 加位置编码（可学习，196+1 个）
  → Transformer Encoder × 12
  → 取 [CLS] 的输出 → MLP head → 分类
```

**关键等价性**：patch embedding 的线性投影**就是** `Conv2d(3, 768, kernel_size=16, stride=16)`——所以 ViT 的第一层本质是"大 stride 卷积"，之后全是全局注意力。

**为什么需要大数据**：

1. 没有卷积的**局部性 + 平移等变**先验（Q9），模型必须从数据里**自己学出**"相邻像素相关""物体平移后应该还是同一类"。
2. 自注意力的参数量大、`O(n²)` 复杂，小数据下容易过拟合。
3. **论文实证**：ImageNet-1k 上 ViT 输给 BiT/ResNet；ImageNet-21k 预训练后反超；JFT-300M 上显著超越。小数据下用 **DeiT** 的蒸馏（用 CNN teacher）能救回来。

**追问**：*`[CLS]` token 是必须的吗？* 不是——也可以用**所有 patch 的 GAP**（很多后续工作这么做，效果相当）。`[CLS]` 的好处是"有一个专门聚合全局信息的槽位"。

**出处**：Dosovitskiy et al., *An Image is Worth 16x16 Words*, ICLR 2021。

## Q34. ViT 的 patch size 怎么选？大 patch 和小 patch 的权衡？★★☆

**参考答案**

| patch | token 数（224²） | 计算量 | 细节 | 适用 |
|---|---|---|---|---|
| 32×32 | 49 | 最小 | 丢细节 | 低分辨率/粗分类 |
| **16×16** | 196 | 中等 | 平衡 | **默认**（ViT-B/16） |
| 8×8 | 784 | 大 4 倍 | 细节丰富 | 分割/检测/细粒度 |
| 4×4 | 3136 | 大 16 倍 | 太贵 | 高分辨率专用（需要窗口注意力） |

**本质权衡**：patch 是"视觉 token"的粒度。**patch 越小 → token 越多 → 注意力 `O(n²)` 爆炸**。`16→8` 时 token 数 ×4，注意力计算 ×16。

**这直接导致了后续架构的两条路**：

1. **层级化 + 窗口注意力**（Swin）：在小 patch 上只算窗口内注意力，控制 `n²`。
2. **卷积 + 注意力的混合**（Hybrid ViT、CoAtNet）：用卷积做早期下采样，减少 token 数。

**工业检测的推论**：小缺陷需要小 patch/高分辨率，但注意力成本爆炸 → 更现实的是"**CNN 骨干 + 局部注意力**"或"**切图 + 中等分辨率**"，而不是纯 ViT 上 4K 图。

## Q35. Swin Transformer 的两个核心设计是什么？为什么这样设计？★★★ 高频

**参考答案**

**① 层级化（hierarchical）**：像 CNN 一样逐级下采样，产出多尺度特征。

```text
Stage 1: H/4  × W/4  × C
Stage 2: H/8  × W/8  × 2C      ← Patch Merging（2×2 邻域拼接 + 线性降维）
Stage 3: H/16 × W/16 × 4C
Stage 4: H/32 × W/32 × 8C
```

**作用**：直接对接 FPN/检测头（ViT 全程同一分辨率，做检测要靠额外设计，如 ViTDet 的简单 FPN）。

**② 窗口注意力 + 移位窗口（Shifted Window）**：

```text
第 L 层：  在 7×7 的窗口内做注意力（窗口不重叠）
第 L+1 层：窗口整体平移 (M/2, M/2)，让相邻窗口"接壤"处产生跨窗口连接
```

**为什么**：窗口内注意力把复杂度从 `O((HW)²)` 降到 `O(HW · M²)`（`M` 是窗口大小，如 7）——**线性于图像大小**。但窗口不重叠会导致"窗口之间永远不交流"，所以隔层平移窗口，**间接实现全局信息流动**。

**③ 相对位置偏置**（第三个要点，常一起问）：在 attention logits 上加一个**可学习的相对位置偏置** `B ∈ R^{(2M-1)×(2M-1)}`，只依赖窗口内的相对坐标，因此可以**跨窗口尺寸/分辨率迁移**（绝对位置编码不行）。

**追问**

- *移位窗口实现上的麻烦？* 平移后窗口大小不整齐，官方用 **cyclic shift（循环移位）+ mask** 的技巧，把不完整的窗口拼成整齐的，最后再移回来。
- *Swin 和 ViT 的本质差别？* ViT 是"全局注意力 + 固定分辨率"，Swin 是"局部注意力 + 层级 + 跨窗交流"——**把 CNN 的归纳偏置部分加了回来**。
- *Swin 的代价？* 窗口内的注意力看不到远处，需要更多层才能建立长程依赖；实现复杂（mask 逻辑）。

**出处**：Liu et al., *Swin Transformer: Hierarchical Vision Transformer using Shifted Windows*, ICCV 2021（最佳论文）。

## Q36. 视觉 Transformer 还有哪些代表工作？各自解决什么？★★☆

**参考答案**

| 模型 | 核心思路 | 解决什么 |
|---|---|---|
| **DeiT** | 用 CNN teacher 做**蒸馏**，加强增强 | 小数据（ImageNet-1k）也能训 ViT |
| **PVT** | 金字塔 + 空间缩减（SRA） | 检测/分割的多尺度需求 |
| **CoAtNet** | 卷积 + 注意力**混合**，深度方向先卷积后注意力 | 兼顾归纳偏置与全局建模 |
| **MAE** | **掩码自编码**：遮 75% patch，重建像素 | 自监督预训练，学强表征（标注少时极有用） |
| **BEiT** | 掩码 + **预测离散视觉 token**（dVAE） | 同上，类似 BERT |
| **DINO** | 自蒸馏 + 无标签 | 自监督，特征对分割/检测迁移极好 |
| **CLIP** | 图文对比学习 | **零样本**分类、开放词汇检测的基础 |
| **ViT-Adapter / ViTDet** | 给纯 ViT 加 FPN/适配器 | 让 ViT 能做检测/分割 |
| **SAM** | 可提示分割（点/框/掩码） | 通用分割基础模型 |

**工业检测里最实用的三个**（结合你的场景）：

1. **MAE/DINO 预训练特征 + 轻量头**：标注只有几百张时，冻结特征 + 线性探测往往比从头训检测器强。
2. **CLIP 做零样本初筛/异常检测**：正常/异常用文本描述，减少标注。
3. **DeiT/蒸馏**：要上 ViT 但数据不够时的性价比方案。

**出处**：Touvron et al.（DeiT, ICML 2021）；He et al.（MAE, CVPR 2022）；Radford et al.（CLIP, ICML 2021）；Kirillov et al.（SAM, ICCV 2023）。

## Q37. ViT 做检测/分割时，最大的障碍是什么？怎么解决？★★☆

**参考答案**

**三个障碍**：

1. **分辨率**：分类用 224²，检测常要 1024²+ → token 数从 196 涨到 4096+，注意力 `O(n²)` 直接爆炸（显存 ×400）。
2. **单尺度**：ViT 全程 `stride=16`，没有 FPN 需要的 `stride=4/8/32` 多尺度。
3. **局部细节**：patch 是 16×16，小目标在 patch 里可能只占几个像素，信息在 patch embedding 时就被"平均"掉了。

**解法**：

- **ViTDet**（何恺明）：保持**朴素 ViT**（不分层），只在**少数几层**加**局部窗口注意力**（其余仍是全局），再用**简单的反卷积 FPN** 得到多尺度——结论是"不需要层级化也能做检测"。
- **Swin/PVT**：层级化 + 窗口，天然给多尺度。
- **ViT-Adapter**：在 ViT 旁边挂一个**卷积侧网络**，注入多尺度空间先验。
- **降低分辨率 + 切图**：工程上最省事，配合 SAHI 做小目标。

**追问**：*为什么 ViTDet 只在少数层用窗口注意力？* 全局注意力在高分辨率下太贵，但完全局部化又丢了 ViT 的全局优势——折中是"**大部分层全局（在低分辨率阶段）+ 少数层局部（在高分辨率阶段）**"，实际上是把计算放在"token 少的早期层"。

---

## Q38. 为什么 ViT 的位置编码用可学习的，而 Swin 用相对位置偏置？★★☆

**参考答案**

**ViT**：固定分辨率（224²）、位置总数固定（196），用 `nn.Parameter(196+1, d)` 最简单，且能学到"图像特有的 2D 结构"（比 1D 正弦更灵活）。**代价**：换分辨率要**插值**位置编码（`F.interpolate` 对 196→576 做双线性），且效果会掉。

**Swin**：窗口会被**移位**、分辨率会变（层级化），绝对位置编码不适用。相对位置偏置只依赖"窗口内两个 token 的相对偏移"，**与绝对位置无关**，所以能跨窗口/跨分辨率复用。

```text
绝对位置编码：pos_embed[i]        ← i 是绝对位置，换尺寸就失效
相对位置偏置：B[Δx, Δy]           ← 只看相对偏移，尺寸无关
```

**这题的深层考点**：位置编码的选择取决于"**模型是否需要跨分辨率泛化**"。分类（固定 224）用绝对编码没问题；检测/分割（多尺度、可变输入）必须用相对编码或插值。

**追问**：*插值位置编码有什么坑？* 1D 正弦编码插值比较自然（连续的），可学习的 2D 编码插值会"糊"（相邻位置被平均），所以高分辨率微调时精度会掉一截。

## Q39. CNN 和 Transformer 能结合吗？有哪些典型方式？★★★（工业落地最实用）

**参考答案**

| 方式 | 代表 | 思路 |
|---|---|---|
| **CNN 骨干 + 注意力模块** | CBAM、Non-local、BoTNet、CoAtNet | 在 CNN 里插注意力，补全局建模 |
| **Transformer 骨干 + 卷积** | Swin、CvT、ViT-Adapter | 用卷积做 embedding/下采样/局部增强 |
| **混合并行** | CoAtNet、Conformer | 浅层卷积（学局部），深层注意力（学全局） |
| **CNN 做 neck/head** | ViTDet、DETR | Transformer 出特征，卷积头做预测 |
| **知识蒸馏** | DeiT | CNN 教 Transformer |

**为什么"浅卷积 + 深注意力"有效**：浅层的任务是"提取边缘/纹理"，这正是卷积的强项（局部、平移等变、参数高效）；深层的任务是"建模语义关系"，这正是注意力的强项。**归纳偏置该用在它该在的地方**。

**工业检测里的实际建议**：

- 小数据（< 5000 张）：**纯 CNN**（ResNet/YOLO）+ 检测头，别硬上 Transformer。
- 中等数据 + 需要长程上下文（大尺寸缺陷、跨区域关联）：**CNN 骨干 + 少量注意力层**（如 YOLOv11 的 C2PSA、或 Swin-Tiny）。
- 数据很少但想用大模型：**冻结 DINO/MAE 特征 + 轻量头**。

## Q40. 自监督在 CV 里怎么做？MAE 的掩码比例为什么这么高？★★☆（加分）

**参考答案**

**三类自监督**：

1. **对比学习**（SimCLR/MoCo）：同图的不同增强互为正样本，其他图为负样本。学"不变性"。
2. **掩码重建**（MAE/BEiT）：遮住一部分 patch，让模型重建像素/离散 token。学"结构理解"。
3. **自蒸馏**（DINO/BeiT v2）：teacher-student，无标签也能学出很好的语义特征。

**MAE 掩码 75% 的原因**（这是它和 NLP 的 BERT 最大不同）：

- 图像**信息冗余极高**：相邻像素高度相关，遮 15%（BERT 的比例）时，模型靠**邻域插值**就能"猜"出被遮的 patch，学不到语义。
- 遮 75% 后，局部线索几乎没了，模型必须**理解全局结构**（这个物体是什么、边界在哪）才能重建。
- 同时 75% 让**编码器只处理 25% 的 token**（MAE 的 encoder 只看可见 patch，decoder 才处理全部）→ 训练**更快**。这是 MAE 相比 BEiT 效率高的关键。

**追问**：*MAE 重建的是像素，为什么也有好特征？* 有争议的解释：重建任务迫使模型编码"语义+结构"，而像素细节由 decoder 承担（decoder 很浅）。论文的消融显示 decoder 深度对线性探测精度影响很小，说明表征主要在 encoder。

**出处**：He et al., *Masked Autoencoders Are Scalable Vision Learners*, CVPR 2022。

# E. DETR 系列

## Q41. DETR 的核心思想是什么？为什么不需要 NMS？★★★ 高频

**参考答案**

**把检测变成"集合预测"（set prediction）**：直接用 Transformer 输出 **N 个固定数量的预测**（N=100），每个预测是 `(类别, 框)`，**不产生重复**，所以不需要 NMS。

```text
图像 → CNN 骨干 → 特征图 (H/32, W/32, 2048)
     → 1×1 降维 + 展平成序列 + 2D 位置编码
     → Transformer Encoder（全局建模）
     → Decoder：100 个**可学习的 object queries** 做 cross-attention
     → 每个 query → FFN → (类别 + 4 维框)
```

**为什么不需要 NMS**：因为训练时用**匈牙利匹配（Hungarian matching）**强制"**一个 GT 只匹配一个预测**"。

```text
代价矩阵 C (100×M)：C[i,j] = λ_cls·分类损失 + λ_box·L1 + λ_giou·GIoU
用匈牙利算法求最优二分匹配，每个 GT 只认领一个 query
没被匹配的 query → 学成 "no object"（∅ 类）
→ 模型学到"一个目标只输出一次"，天然去重
```

**这是 DETR 最漂亮的地方**：去重从"后处理（NMS）"变成了"**训练时的监督信号**"。

**追问**

- *匈牙利匹配会不稳定吗？* 会——早期预测乱，匹配可能"跳来跳去"；所以 DETR 用了**辅助损失**（每层 decoder 都算 loss）帮助收敛。
- *100 个 query 够吗？* 不够就加；COCO 上 100 够用，密集场景要加到 300/500（成本线性增长）。

**出处**：Carion et al., *End-to-End Object Detection with Transformers*, ECCV 2020。

---

## Q42. DETR 为什么收敛这么慢（500 epoch）？根本原因是什么？★★★（高频追问）

**参考答案**

**现象**：DETR 要 500 epoch，Faster R-CNN 只要 12–36 epoch。

**根本原因**（三条，前两条是核心）：

1. **注意力初始是"均匀"的**：初始化时 `Q·Kᵀ ≈ 0`，softmax 输出接近 `1/n`——也就是说**一开始每个 query 都在"平均地看全图"**，没有任何空间聚焦。模型必须从"均匀"慢慢学出"聚焦到某个物体"，这个过程极慢。
2. **匈牙利匹配的不稳定**：早期预测质量差，匹配结果随机跳变，一个 query 这一轮学这个物体、下一轮学那个 → 优化目标本身在变。
3. **没有先验**：不像 anchor 那样有"位置先验"，query 是**纯可学习**的，从零学"该关注哪里"。

**Deformable DETR 怎么解决**：把"看全图"换成"**只看少数几个采样点**"（Q43），并且这些采样点的**初始位置来自特征图上规则的网格**（相当于给了位置先验），于是"聚焦"这件事几乎不用学。

**其他改进**：

- **DINO**：contrastive denoising（给 query 加噪声，让模型学会"去噪"）+ mixed query selection（用 encoder 输出初始化 query 的位置）+ look forward twice。
- **条件化 query**（Conditional DETR）：用 anchor 位置生成 query 的内容部分。

**面试时的说法**："慢的本质是**注意力缺少空间先验 + 匹配不稳定**，Deformable 用'稀疏采样 + 网格先验'同时解决了这两点，所以能 10 倍加速收敛。"

---

## Q43. Deformable Attention 是怎么工作的？为什么能快这么多？★★★ 高频

**参考答案**

**标准注意力**：每个 query 和**所有** `n` 个 key 算权重 → `O(n²)`。
**Deformable 注意力**：每个 query 只在**少数 K 个采样点**上做加权（K 默认 4），采样点的位置由 query 通过一个**可学习的偏移量**预测出来。

```text
对每个 query（reference point）：
  1. 线性层预测：Δp（K 个采样偏移）+ A（K 个注意力权重）+ 特征变换
  2. 在 reference point + Δp 处，用**双线性插值**取特征
  3. 加权求和：out = Σ_{k=1}^{K} A_k · V(p + Δp_k)

复杂度：O(n · K · d)   vs  O(n² · d)
```

```text
标准注意力：                可变形注意力：
q ──┬──────────────► 全部 n 个点    q ──► 预测 4 个偏移 ──► 只取 4 个点
    └ 权重由 q·k 决定                 权重也由 q 预测
```

**为什么快**：

1. **复杂度从 `O(n²)` 降到 `O(nK)`**（K=4），高分辨率特征图（`stride=8`，上万 token）才可行。
2. **多尺度**：可以在**多个尺度的特征图**上采样（每个 query 在每层采几个点），天然融合多尺度（解决 DETR 小目标差的问题）。
3. **收敛快 10 倍**：采样点的**初始位置**来自规则网格（reference point），相当于给了"位置先验"，不用从均匀分布慢慢学（Q42）。

**代价**：

- 需要**自定义算子**（双线性采样 + 反向），部署到 TRT 要写插件；
- 采样点可能落在无意义区域（但有 learnable offset 可以修正）。

**追问**：*"可变形"这个名从哪来？* 来自 Deformable Conv（DCN）：卷积核的采样位置可以偏移。这里是把同样的思想用到注意力上（采样点在空间上可变形）。

**出处**：Zhu et al., *Deformable DETR: Deformable Transformers for End-to-End Object Detection*, ICLR 2021。

---

## Q44. DETR 输出 100 个预测，但图里只有 3 个目标，剩下 97 个怎么办？★★☆

**参考答案**

剩下 97 个 query 被训练成预测 **"no object"（空类）**——在匹配时它们没有被任何 GT 认领，于是分类目标就是 `∅`。

**推理时**：按分类置信度过滤（阈值，如 0.5），或者取 **top-k**（k = 预期最大目标数）。

**关键工程点**：

1. **空类的样本不均衡**：97:3，所以 DETR 对空类用了**降权**（`eos_coef = 0.1`），否则模型会倾向于全预测空类。
2. **数量上限**：`N=100` 意味着**一张图最多检出 100 个目标**。密集场景（成百上千的零件）必须调大 `N`（如 300/900），成本线性上涨——这是 DETR 在密集场景的一个实际限制。
3. **"no object" 的分数不可靠**：它不是"背景分"（不像 YOLO 的 objectness），语义不同，别拿它当阈值调。

**追问**：*为什么用固定 N 而不是动态数量？* 集合预测要求输出集合大小固定（才能做二分匹配）；动态数量需要额外的机制（如 DETR 的 "cardinality" 预测变体）。

## Q45. DETR 系（DETR / Deformable / DINO）的演进主线是什么？★★☆

**参考答案**

| 模型 | 核心问题 | 解决 |
|---|---|---|
| **DETR**（2020） | 端到端可行，但收敛慢、小目标差 | 集合预测 + 匈牙利匹配 |
| **Deformable DETR**（2021） | 收敛慢、`O(n²)`、单尺度 | 可变形注意力 + 多尺度 + 迭代框精化 |
| **Conditional DETR**（2021） | query 无位置先验 | 用 anchor 位置生成 query 的内容部分 |
| **DAB-DETR**（2022） | query 语义不清 | 把 query 显式定义为 4D anchor（x,y,w,h） |
| **DN-DETR**（2022） | 匹配不稳定 | 加**去噪训练**（给 GT 加噪声让模型重建） |
| **DINO**（2023） | 综合改进 | contrastive denoising + mixed query selection + look forward twice |
| **RT-DETR**（2024） | 实时性 | 高效混合编码器 + IoU-aware query 选择，**首个实时端到端检测器**（超过同速 YOLO） |

**主线一句话**：**DETR 证明了"无 NMS 端到端"可行；后续所有工作都在解决"慢"和"小目标"，方法集中在三处：注意力稀疏化（Deformable）、query 初始化（DAB/DINO 的 anchor/selection）、训练信号（去噪/辅助损失）**。

**面试时的加分点**：提到 **RT-DETR**——它说明 DETR 系已经能实时，NMS 不再是必须，工业上"端到端 + 固定延迟"的吸引力越来越大。

# F. Transformer 的应用与工程问题

## Q46. Transformer 的 `O(n²)` 到底卡在哪？实际怎么绕过？★★★

**参考答案**

**卡在两处**：

1. **计算**：`Q·Kᵀ` 是 `n²d` 次乘加。
2. **显存**：要存 `n×n` 的注意力矩阵（训练时还要存反向的中间量）。

以 `n = 4096`（1024² 图像、`stride=16`）、`d = 768`、fp16 计：单个注意力矩阵 `4096² × 2B = 32 MB`，12 层 × 12 头 → 直接爆。

**四条绕过路径**：

| 方向 | 代表 | 复杂度 | 代价 |
|---|---|---|---|
| **局部窗口** | Swin、ViTDet | `O(n·w²)` | 丢失全局（靠层叠/移位补） |
| **稀疏/可变形** | Deformable DETR、DAT | `O(nK)` | 自定义算子、采样可能漏 |
| **线性/核方法** | Linear Transformer、Performer | `O(n)` | 精度有损 |
| **IO 优化** | FlashAttention | `O(n²)` 但显存 `O(n)` | 只省显存和带宽，不改复杂度 |
| **下采样/池化** | PVT 的 SRA、token merging | `O(n)` | 丢细节 |

**工程决策的顺序**（这是真正值钱的经验）：

1. 先问**分辨率是否真的需要这么大**（很多检测任务 640 已经够）；
2. 需要高分辨率就用**层级化 + 窗口**（Swin/PVT），成熟且部署友好；
3. 追求极限速度才上稀疏/线性注意力；
4. **FlashAttention 是"免费"的**（精确、只需装库），任何全局注意力都该开。

---

## Q47. 为什么高分辨率下的检测/分割更多用 CNN 而不是 Transformer？★★☆

**参考答案**

**四个现实原因**：

1. **复杂度**：分割常要 `stride=4` 的输出（1024² 图 → 65536 token），全局注意力 `O(n²)` = 43 亿次/层，不可行；CNN 是 `O(n·k²·C²)`，线性于像素数。
2. **细节保留**：patch 化（16×16）在 embedding 阶段就把小目标"平均"掉了；CNN 的浅层特征保持全分辨率。
3. **数据**：分割标注贵（像素级），数据集通常小；Transformer 缺归纳偏置，小数据不划算。
4. **部署**：CNN 有成熟的 INT8 量化、TRT 融合；Transformer 的动态 shape、自定义算子（可变形采样）麻烦。

**但趋势在变**：Swin/PVT 在 ADE20K 上已经超过 CNN；**混合架构**（CNN 骨干 + 注意力 neck）是当前性价比最高的选择。**结论要说得平衡**：不是"Transformer 不行"，而是"**在数据/分辨率/部署的三重约束下，CNN 或混合架构更划算**"。

---

## Q48. 把 Transformer 部署到产线，会有哪些坑？★★★（你的优势题）

**参考答案**

**① 动态 shape**：Transformer 的序列长度 = `H/P × W/P`，输入尺寸一变，序列长度就变 → TRT 要开多个 optimization profile，否则重建引擎（几十秒）。**建议**：固定输入尺寸，或按业务分几档。

**② 算子支持**：

- `LayerNorm`：TRT 支持，但**EPS 位置**和 PyTorch 可能不一致（`(x-μ)/sqrt(σ²+eps)` vs `sqrt(σ²)+eps`），导出后精度会差 → 必须逐层对齐输出。
- `GELU`：早期的 TRT/ONNX 只有 tanh 近似，和 PyTorch 的精确版有微小差异（`1e-3` 级），累积后可能影响 0.1% 精度。
- **可变形注意力 / 窗口移位**：**没有原生算子**，要写插件或改成等效的 dense 实现（慢）。
- `softmax` 的数值稳定性：fp16 下大 logits 会溢出 → 用 fp32 或减最大值。

**③ 精度**：Transformer 对量化更敏感（尤其 INT8），LN 和 attention 的分布跨度大 → 常需要 **partial quantization**（LN/softmax 保 fp16，其余 INT8）。

**④ 显存/带宽**：注意力是 memory-bound，小 batch 下 GPU 利用率低 → 增大 batch、用 **KV cache**（自回归）或 **channels_last**。

**⑤ 后处理**：DETR 无 NMS 是优势，但 top-k 选择和阈值过滤在 GPU 上做要小心同步（`.item()` 会断流水线）。

**回答框架**：先说"**先做逐层数值对齐，再谈性能**"，再按"算子 → 精度 → shape → 后处理"顺序讲。这个顺序体现你踩过坑。

## Q49. Transformer 的显存主要花在哪？训练和推理有什么不同？★★☆

**参考答案**

**训练**（`n` token、`d` 维、`L` 层、`b` batch、`h` 头）：

```text
① 参数：~12·L·d²
② 梯度：同参数
③ 优化器状态（Adam）：2×参数
④ 激活：L × b × n × d × (若干倍)   ← 大头
⑤ 注意力矩阵：b × h × L × n²       ← 第二大头（可用 FlashAttention 消掉）
```

以 ViT-B（`L=12, d=768`）、`n=196`、`b=64` 为例：参数+梯度+优化器 ≈ 1.5 GB；激活和注意力矩阵远超它。

**推理**：

- **无梯度、无优化器** → 显存 ≈ 参数（fp16 减半）+ 激活（单层即可释放）+ **KV cache**（自回归时）。
- **KV cache 是 LLM 推理的主要开销**：`2 × L × n × d × 2B`，长上下文时能超过模型本身 → MQA/GQA/PagedAttention 都是为了压它。

**省显存的顺序**（工程上）：`FlashAttention`（免费）→ 降 batch/分辨率 → **梯度检查点** → 混合精度 → 分片（FSDP）。

## Q50. 如果让你给一个 500 张图的工业缺陷数据集选模型，你怎么决策？★★★（综合题）

**参考答案**（按"约束 → 候选 → 验证"的结构答）

```text
约束：
  数据量 500 张（极少）    → 不能从头训大模型
  缺陷形态未知             → 先做错误分析再选结构
  产线要可解释/可复现      → 优先成熟工具链
  延迟要求？               → 决定模型规模

候选路线（按数据量从小到大）：
  ① 传统 CV（模板匹配/差分/形态学）——如果缺陷是"确定的异常"，往往 20 行代码就够
  ② 预训练 CNN + 轻量头（ResNet/EfficientNet + FPN/检测头）——最稳的基线
  ③ 冻结 DINO/MAE 特征 + 线性/浅层头——500 张也能work
  ④ 异常检测（PatchCore/PaDiM）——只有正常样本时唯一选择
  ⑤ 微调检测器（YOLO + 强增强 + 冻结骨干）——能做，但要防过拟合

验证方式（比选模型更重要）：
  按批次切分 train/val（防泄漏）
  固定 bad case 集做回归
  看漏检率/过杀率，不看 mAP
```

> "500 张图我不会先纠结 Transformer 还是 CNN，我会先看**缺陷的成像特征**。如果是低对比、小面积、形态固定，传统方法 + 简单分类器可能就够了，还不用标注框；如果形态多变，我用预训练骨干 + 检测头，并做**跨批次验证**。Transformer 在这个数据量下我只会用**冻结特征**的方式，不会微调整个模型。"

## Q51. 注意力能替代卷积吗？说说你的判断。★★☆（观点题）

**参考答案**

**能替代的部分**：全局建模、长程依赖、动态权重（content-based 的核）。

**不能/不该替代的部分**：

1. **局部特征提取的效率**：卷积的参数量、计算量、平移等变都是"白送"的，注意力要**从数据学**这些，代价是数据和算力。
2. **高分辨率输入**：`O(n²)` 让注意力在高分辨率下不可行（Q47）。
3. **部署友好性**：卷积的 INT8 量化、算子融合、各种硬件加速器支持远好于注意力。

**我的判断**（可以这么答）：

> "短期是**混合**：CNN 做浅层/高分辨率，注意力做深层/低分辨率。长期如果算力和数据都不是瓶颈，纯注意力的上限更高——但'上限高'和'工程上更划算'是两件事。ViT 论文自己的结论就是：数据足够大时它才反超，这句话反过来读就是'数据不够时别用'。"

**别报菜名，按"问题—方案"讲**：

# G. 快问快答（45 题）

> 一题一行结论。CNN/检测 20 题 + Transformer 25 题。

**Q53** 卷积的参数量与输入分辨率有关吗？ —— **无关**，只与 `k`、`C_in`、`C_out` 有关。但 **FLOPs 与输出分辨率成正比**——所以同一个模型跑 4K 和 640，参数量一样、计算量差 40 倍。这解释了"模型不大但很慢"。

**Q54** 卷积后尺寸怎么算？ —— `out = floor((in + 2p − k)/s) + 1`。要保持尺寸不变（`same`），奇数核取 `p = (k−1)/2`、`s = 1`；偶数核（如 2×2）做不到严格 same。

**Q55** `stride=2` 的卷积和 `maxpool` 谁更好？ —— 现代骨干基本用 **`conv s=2`**：下采样**可学习**、无 max 的梯度稀疏问题、少一次算子启动。maxpool 的优势是零参数、更抗噪（适合浅层做细节保留）。

**Q56** 转置卷积是卷积的逆吗？ —— **不是**。它只是"按卷积的转置方式做上采样"（`s>1` 时会在输入元素间插零再卷积），**不能还原原图**——多个输入会产生同一个输出，信息已经丢了。

**Q57** 可变形卷积（DCN）在做什么？ —— 卷积核的**采样点位置**由输入预测偏移量（`offset`），使核能"贴合"不规则形状（弯曲的划痕、细长缺陷）。代价是采样不规则、**部署要自定义算子**。

**Q58** SE 模块和 CBAM 的区别？ —— SE 是**通道注意力**（全局池化 → FC → 每个通道一个权重）；CBAM 是**通道 + 空间**双注意力（再加一层空间图）。都是"廉价地重标定特征"，SE 更轻、CBAM 更细。

**Q59** FPN 的两个连接是什么？ —— **横向连接**（各层 1×1 卷积对齐通道）+ **自上而下**（高层上采样后相加）。让浅层获得语义、深层获得细节。

**Q60** PANet 相比 FPN 多了什么？ —— 一条**自下而上**的通路（把浅层的定位信息再传回深层）。代价是参数/延迟增加，但对**小目标和定位精度**有稳定收益（YOLOv4/v5 都用）。

**Q61** BiFPN 的改进？ —— ① 跨层**加权**融合（不同尺度的贡献不等权）；② **重复堆叠**同一个 block（等价于更深的多尺度融合）；③ 去掉只有一个输入的节点（简化）。

**Q62** 特征图 stride 与最小可检测目标的关系？ —— 经验上目标的**最小边不应小于 stride**（`stride=8` 时小于 8 px 的目标基本学不到）。所以小目标要靠**更浅的层（stride=4）**或**切图**，而不是调 loss。

**Q63** anchor 的尺寸怎么定？ —— 对训练集的 GT 框做 **k-means 聚类**（用 IoU 距离而非欧氏距离），得到 k 组 `(w,h)`。COCO 的 anchor 套到工业缺陷上通常完全不合适（缺陷形状和高宽比分布差很远）。

**Q64** 正负样本比例多少合适？ —— 没有固定值。单阶段一图有上万个 anchor，正样本可能只有几十个（1:1000+）。靠 **focal loss / 采样 / 动态分配**解决，而不是"调到一个神奇比例"。

**Q65** OHEM 是什么？ —— 在线难例挖掘：每步只挑 loss 最大的那部分负样本参与反传，压制大量易分背景。是 focal loss 出现之前的常规手段。

**Q66** Focal Loss 的 `γ` 在做什么？ —— `−α(1−p)^γ log p`。`γ` 越大，**易分样本（p→1）的权重被压得越狠**。`γ=2` 是 RetinaNet 的经验值；`γ=0` 退化成加权 CE。

**Q67** GIoU、DIoU、CIoU 各加了什么？ —— GIoU 加"**最小外接框**"惩罚（处理不重叠）；DIoU 加"**中心点距离**"；CIoU 再加"**长宽比一致性**"。三者都在解决"L1 损失对尺度不敏感"的问题。

**Q68** NMS 阈值调大调小分别有什么后果？ —— 调**小**（如 0.3）：抑制更狠 → 密集目标漏检；调**大**（如 0.8）：抑制不足 → 重复框多。0.5 是通用起点，密集场景要 0.6–0.7 或换 Soft-NMS。

**Q69** COCO 的 mAP 怎么算？ —— 对每个类别按置信度排序画 PR 曲线，用**101 点插值**算 AP，再对 80 类取平均。`mAP@[.5:.95]` 是 IoU 从 0.5 到 0.95 步长 0.05 的 10 个 AP 再平均。

**Q70** `mAP@0.5` 和 `mAP@[.5:.95]` 差在哪？ —— 前者只看"框大致对"（IoU>0.5），后者要求**定位精度**。**工业测量场景关心的是后者（甚至 IoU>0.9）**，因为框偏 3 个像素可能就判错了。

**Q71** Precision 和 Recall 在检测里怎么定义？ —— `P = TP/(TP+FP)`（报出来的里有多少是对的）、`R = TP/(TP+FN)`（真的里找到了多少）。**漏检看 Recall、过杀看 Precision**，业务上要先定哪个更贵。

**Q72** 为什么"提高置信度阈值"能提高 Precision 但掉 Recall？ —— 阈值提高 → 只保留高置信预测 → FP 减少（P 升）但同时漏掉低分真目标（R 降）。**这是同一个权衡的两个面**，业务阈值必须按成本定。

**Q73** 多尺度训练的作用？ —— 让模型适应不同尺度（增强尺度鲁棒性），同时"放大"小目标（缩图后大目标变小、原图小目标相对变大）。代价是 BN 统计量和输入尺寸耦合，**小 batch + 多尺度容易不稳**。

**Q74** TTA 一般怎么做、什么时候不值得？ —— 水平翻转 + 多尺度，预测后融合（WBF 或 NMS）。**精度能涨 1–2 个点，但延迟翻几倍**——工业产线基本不用（延迟不允许），离线评估可以用。

**Q75** label smoothing 为什么有用？ —— 防止模型对单一类别过度自信（把 1.0 目标改成 0.9），改善校准和泛化。**但它会破坏"置信度可解释性"**——用了它，分数就不能直接当概率用。

**Q76** EMA（指数移动平均）权重为什么要存？ —— 训练末期的权重在高 lr 下抖动，EMA 是"参数的滑动平均"，通常比最后一步的权重要稳、指标略高。**几乎零成本的涨点手段**，但要额外存一份参数（显存 ×2）。

**Q77** 骨干用 ImageNet 预训练还有用吗？ —— 在数据少于 10 万时**几乎总是有用**（收敛快、最终精度高）；数据极大时收益变小。**注意输入域差异**：ImageNet 是自然图像，工业灰度/红外图像的迁移效果会打折，但**仍比随机初始化好**。

**Q78** ViT 的 `[CLS]` token 和 GAP 哪个好？ —— 效果相当（很多后续工作直接用 GAP）。`[CLS]` 的好处是有**专门的聚合槽位**、且不依赖 patch 数；GAP 更简单、少一个参数。

**Q79** 注意力的 softmax 是在哪个维度做的？ —— 在 **key 维（最后一维）** 上做的，即每个 query 对所有 key 的权重和为 1。搞错维度会让权重沿 query 归一化，语义完全不同。

**Q80** 位置编码能做长度外推吗？ —— 可学习的位置编码**不能**（训练长度外的位置没有参数）；正弦编码理论上可以但实际会掉点。常用做法是**插值**（把 `196` 个位置插值到 `576` 个），或改用相对位置/RoPE。

**Q81** Swin 的 Patch Merging 具体做什么？ —— 把 2×2 邻域的 4 个 token 在**通道维拼接**（`4C`），再线性降维到 `2C`。等价于"stride=2 的下采样 + 通道翻倍"，形状变化和 CNN 的 stage 过渡一致。

**Q82** Swin 的窗口大小为什么取 7？ —— 经验值：`7×7=49` 个 token 的窗口，在注意力成本和"窗口内能看到多大范围"之间平衡；`M=7` 时移位 `M/2` 不是整数，实现上用 `M//2=3`。取 8 或 12 也能work，7 是论文的选择。

**Q83** DETR 的 object query 是什么？ —— **可学习的 embedding**（N=100 个向量），不是从图像里提取的。它们作为 decoder 的输入，通过 cross-attention"查询"图像特征——**每个 query 学成一个"检测槽位"**。

**Q84** 匈牙利匹配的代价矩阵由什么构成？ —— 分类概率（`−log p`）+ L1 框距离 + GIoU 距离，各自带权重 `λ_cls, λ_L1, λ_giou`。**权重选择会显著影响收敛速度**，这是 DETR 调参最敏感的地方之一。

**Q85** DETR 的辅助损失是什么？ —— **每一层 decoder 的输出都接一个预测头并算 loss**（不是只用最后一层）。作用是给中间层直接的监督信号，缓解"深层才开始学对"的问题，明显加快收敛。

**Q86** Deformable Attention 的 reference point 从哪来？ —— 初版来自**特征图上的规则网格**（每个 query 对应一个位置），后续迭代版本（iterative refinement）用**上一轮预测的框中心**更新。这就是"给了位置先验"的来源。

**Q87** 多尺度可变形注意力怎么融合不同层？ —— 每个 query 在**每一层特征图**上都采 K 个点，各层分别加权后**求和**（权重也由 query 预测，跨层归一化）。所以它天然是多尺度的，不需要额外的 FPN。

**Q88** DN-DETR / DINO 的 denoising 在做什么？ —— 给 GT 框**加噪声**（加噪框 + 类别），作为额外 query 送进 decoder，要求模型**还原出干净的 GT**。这让模型学会"从近似框修正到准确框"，绕开了匈牙利匹配的不稳定。

**Q89** RT-DETR 的混合编码器是什么？ —— **AIFI**（只在最高层做自注意力，降低计算）+ **CCFM**（跨尺度特征融合，用卷积）。核心思想：**别在所有尺度上做注意力**，只在最需要全局信息的低分辨率层做。

**Q90** CLIP 的损失是什么？ —— **对称 InfoNCE**：一个 batch 里 N 个图文对，图像和文本互为对比，正样本是对角线，负样本是其他 N−1 个。温度参数 `τ` 可学习。学到的是"图文对齐的联合嵌入空间"。

**Q91** SAM 由哪三部分组成？ —— ① **图像编码器**（ViT-H，重，一张图跑一次）；② **prompt encoder**（点/框/掩码 → embedding）；③ **mask decoder**（轻量，几毫秒）。所以"同一张图反复给不同 prompt"很便宜——重计算只在图像编码。

**Q92** MAE 重建的是什么？ —— **被遮 patch 的归一化像素值**（每 patch 减均值除方差）。只算被遮部分的 loss（可见部分不算），且 encoder 只看可见 patch（省 75% 计算）。

**Q93** `attention` 的复杂度到底是 `O(n²d)` 还是 `O(n²)`？ —— 两者都对但含义不同：**相似度矩阵是 `O(n²)` 个元素**（显存），**计算量是 `O(n²d)`**（`QKᵀ` 和 `·V` 各一次）。讨论"能不能跑"时看前者，讨论"快不快"时看后者。

**Q94** 为什么 Transformer 的 LayerNorm 放在子层**之前**（Pre-LN）更稳？ —— 残差通路上**没有 LN**（`x + f(LN(x))`），梯度可以无损回传；Post-LN 的梯度必须穿过 LN，深层时尺度失衡，必须靠 warmup 救。

**Q95** 为什么视觉 Transformer 常把 `qkv_bias` 设成 True？ —— 视觉任务没有文本的位置偏置结构，**加 bias 让模型更容易学到绝对位置/常量偏移**；NLP 里常设 False（因为位置编码已经提供了）。这个细节在 DeiT/Swin 的实现里都能看到。

**Q96** DropPath（随机深度）和 Dropout 的区别？ —— Dropout 丢**神经元**；DropPath 丢**整个残差分支**（整层/整个 block 直通）。深层 Transformer/ResNet 常用它正则化（`stochastic_depth`），**推理时按概率缩放**。

**Q97** 视觉 Transformer 的 token 数为什么不能太大？ —— 因为注意力是 `O(n²)`：`n` 翻倍，显存/计算翻 4 倍。`n=196`（224/16）很轻，`n=4096`（1024/16）就爆了——这是"ViT 做检测难"的根本原因。

# H. 深挖题（6 题）

## Q98. mAP 有哪些盲区？工业场景该怎么评？★★★（这题最能体现工程判断）

**参考答案**

**mAP 的五个盲区**：

1. **被大量易分样本稀释**：一张图几十个目标，平均下来一个关键缺陷漏检只让 mAP 掉 0.1%，但业务上可能是致命的。
2. **IoU 阈值与业务脱节**：`IoU=0.5` 对"划痕长度测量"毫无意义——框偏 5 像素，IoU 还在 0.8 以上。
3. **不区分错误代价**：把 A 类缺陷判成 B 类，和判成背景，惩罚一样（都是 FP+FN），业务上完全不同。
4. **不看置信度校准**：mAP 只看排序，不看"分数是不是概率"。**线上要按分数设阈值**，就需要校准（temperature scaling / isotonic）。
5. **不反映分布外**：训练集没有的场景（新工位、新光照），mAP 完全无法预警。

**工业场景该看的四个指标**：

```text
① 按类别的召回率 @ 固定过杀率（"在允许 1% 过杀的前提下，漏检多少"）
   —— 这才是产线能接受的表述方式

② 按缺陷尺寸/位置切片的召回
   —— 小缺陷、边缘区域通常最差，整体 mAP 会把它藏起来

③ 重复性（同一张图重复跑 10 次的结果一致性）
   —— 阈值贴边时，模型输出的微小抖动会导致判定翻转

④ P99 延迟（不是平均延迟）
   —— 产线节拍由最慢的那 1% 决定
```

**面试时可以这么说**：

> "我不看 mAP 决定上线。mAP 用来**比模型**，上线用**业务指标**：在固定的过杀率下，各类缺陷的召回率是多少、小尺寸缺陷的召回是多少、同一批图跑两遍结果一致吗。这些指标不达标，mAP 再高也不能上。"

**追问**：*怎么定阈值？* 在验证集上画**每一类的 PR 曲线**，找"满足过杀率上限"的最低阈值；然后**留出 20% 数据做阈值验证**（在同一批数据上定阈值再评估，会高估）。

## Q99. 检测模型的时间预算怎么拆？优化该从哪下手？★★★

**参考答案**

**先拆再优化**。以 640×640 输入的 YOLO 类模型（桌面 GPU、TRT fp16）为例的**量级**：

```text
阶段              占比（量级）    说明
────────────────────────────────────────────
预处理（CPU）      5–20%         resize + 归一化 + H2D；大图时更高
Backbone          40–60%        与输入分辨率强相关
Neck (FPN/PAN)    15–25%        多尺度融合，高分辨率层贵
Head              5–10%         解耦头在小模型上反而占比高
NMS / 后处理      5–20%         密集目标时可能是最大单项
```

（**数字随模型/硬件差异很大，面试时应说"量级"而不是报死数**。）

**优化顺序**（按投入产出）：

1. **先 profile**（`nsys` / TRT 的逐层耗时），别猜。**猜错方向是最常见的浪费**。
2. **后处理**：NMS 换 CUDA 版、先按分数阈值裁剪（把候选从几十万降到几千）。
3. **预处理**：移到 GPU（DALI / TRT 预处理插件）、固定 resize 尺寸、避免 BGR↔RGB 来回转。
4. **Backbone**：换更轻的骨干 / 降分辨率 / 用 `channels_last` + TF32。
5. **Neck**：减少高分辨率层的通道数（`stride=4` 那层最贵）。
6. **Head**：解耦头对小模型是负担，可以共享部分卷积。
7. **量化**：INT8 + 校准集，通常 1.5–2 倍（**要按业务指标验证，不能只看 mAP**）。

**一个反直觉的结论**（可以说，很加分）：

> "在小模型 + 密集目标场景，**NMS 常常比 backbone 还贵**。我遇到过一次 DT 只有 12 ms、后处理 9 ms 的情况——把 NMS 换 CUDA 版之后总延迟直接砍半，比换模型有效得多。"

**追问**：*批处理一定更快吗？* 吞吐更高，但**单帧延迟变差**（要等 batch 凑齐）。产线要的是**延迟确定性**，所以常固定 batch=1 或极小 batch。

## Q100. 标签分配为什么和损失函数耦合？OTA/TAL 的思想是什么？★★★

**参考答案**

**核心洞察**：损失函数定义"预测和 GT 差多少"，但**先得决定"哪个预测对哪个 GT 负责"**。分配错了，再好的损失也在优化错误的目标。

```text
分配（assignment）  →  损失（loss）
"谁负责学这个 GT"      "学得多像算合格"
        ↑                    │
        └──── 互相影响 ───────┘
   分类分高的点更该当正样本；正样本的 loss 又塑造分类分
```

**演进**：

| 阶段 | 方法 | 问题 |
|---|---|---|
| 静态 | IoU > 0.5 为正 | 阈值对尺度敏感；小目标正样本少 |
| 自适应阈值 | **ATSS**：按 IoU 的均值+标准差算阈值 | 仍依赖 IoU |
| 全局最优 | **OTA**：把分配写成**最优传输**问题（全局求解） | 慢（Sinkhorn 迭代） |
| 近似全局 | **SimOTA**（YOLOX）：取 top-k 后用"动态 k"近似 | 快，效果好 |
| 任务对齐 | **TAL**（YOLOv8）：`score = cls^α · iou^β` | 让"分类好且框准"的点优先 |

**TAL 的具体做法**（能讲清这个就够）：

```text
① 对每个 GT，算所有 anchor 的 alignment metric：
     t = s^α · u^β        s=分类分, u=IoU, α=β=1（默认）
② 每个 GT 选 top-k（k 由 IoU 之和动态决定）作为候选正样本
③ 同时约束"一个 anchor 最多负责一个 GT"（按 t 最大者领取）
```

**为什么这样更好**：分类和回归**共用同一个点**，如果分配时只看 IoU，会出现"框准但分类差"的点被选为正样本 → 分类头和回归头互相打架。TAL 的 `s^α·u^β` 强制两个任务**对齐**。

**追问**：*动态分配会不会早期不稳定？* 会。常见对策：**warmup 期用静态分配**（前几个 epoch），之后再切动态；或加 denoising（DINO 的做法）提供稳定信号。

## Q101. 工业检测的数据增强该怎么做？为什么 COCO 的配方会害你？★★★

**参考答案**

**原则：增强必须"物理上可能"**。增强的本质是"模拟数据分布的变化"，如果模拟出的图像在现实中不可能出现，模型就学到了**伪相关**。

**COCO 增强在工业场景的三个危害**：

| 增强 | 在 COCO 里为什么好 | 在工业里为什么有害 |
|---|---|---|
| **Mosaic（4 图拼接）** | 增加小目标、提升 batch 多样性 | **拼接线被学成缺陷**；缺陷被截断成"半个缺陷"，标注与外观不一致 |
| **大幅旋转/缩放/透视** | 适应拍摄角度变化 | 工位固定、视角固定；乱变会让"划痕"变成"污渍" |
| **强色彩抖动** | 适应光照/白平衡变化 | 颜色本身可能是判别依据（锈 vs 油污），抖没了就分不开 |

**该怎么做**（按优先级）：

```text
① 光照类（安全）：亮度/对比度的**小幅**线性变化、gamma 微调、模拟曝光波动
② 噪声类（安全）：高斯噪声（匹配 sensor 的噪声模型）、轻微 JPEG 压缩
③ 模糊类（谨慎）：轻微运动模糊/离焦——**如果实际会失焦就该加**
④ 几何类（受限）：**小角度**旋转（±5°）、**小比例**缩放（±10%）、水平翻转（仅当缺陷无方向性）
⑤ 缺陷级（最有效）：复制粘贴缺陷到不同背景（Copy-Paste）、生成式合成
```

**关键判断**：

- **缺陷有方向性吗？** 划痕有方向 → 不能随意旋转；污渍无方向 → 可以。
- **颜色是判别依据吗？** 是 → 不能强色彩抖动。
- **会有遮挡/截断吗？** 现实中不会 → 不要 Mosaic。

**我自己的规矩**（可以照说）：

> "每条增强我都会问一句：**这个变换后的图，在产线上拍得出来吗？** 拍不出来就不加。宁可增强少一点、靠多采数据，也不要让模型学到现实中不存在的外观。"

**追问**：*那数据少怎么办？* ① Copy-Paste（把真实缺陷贴到真实背景上，物理上成立）；② 生成式合成（但要验证"合成缺陷的真实性"，否则引入域差异）；③ **异常检测**（只用正常样本训练），这是数据极少时的正解。

## Q102. 小目标检测：从信息论角度分析，瓶颈到底在哪？★★★（加分）

**参考答案**

**先算一笔账**（这是这题的杀伤力所在）：

```text
假设输入 1024×1024，backbone stride=32 → 特征图 32×32
一个 16×16 像素的目标 → 在 stride=32 的图上只占 0.5×0.5 个格子
                       → 经过 5 次下采样后，几乎没有任何独立信息
（每次 stride=2 的卷积都可能把 16px 压到 8px → 4px → 2px → 1px）
```

**四个瓶颈，按"能不能救"排序**：

| 瓶颈 | 能否解决 | 手段 |
|---|---|---|
| **特征图分辨率不足**（信息被下采样丢掉） | ✅ 能 | 更浅的检测头（stride=4/8）、切图、提高输入分辨率 |
| **标注质量**（小目标的框本身就标不准） | ⚠️ 难 | 放大标注、亚像素标注、一致性检查；**小目标的 IoU 噪声极大** |
| **正样本太少**（分配时被饿死） | ✅ 能 | ATSS/TAL 自适应、降低小目标的匹配阈值 |
| **物理信息不足**（目标本身对比度低/被噪声淹没） | ❌ 不能 | 只能改**成像**：镜头、光源、曝光、偏振。算法无能为力 |

**最重要的一条结论**（面试时说出来很有分量）：

> "小目标检测有一半问题**不在算法里**。如果缺陷在图上只占 8 个像素、和背景的对比度只有 5 个灰度级，那它已经接近成像系统的极限了——这时候调 loss、换模型都是白费，应该去改**光学和照明**。我在项目里会先确认'这个缺陷在最佳成像条件下能有多清楚'，再决定算法投入多少。"

**能救的部分怎么做**：

1. **切图（tiling）**：把 4K 切成 512×512 重叠块 → 目标相对变大，但**边界目标会被切断**，要重叠 + 合并去重（SAHI 的做法）。
2. **高分辨率浅层头**：`stride=4` 的头，配合 FPN 把语义传下来。
3. **超分预处理**：有争议——超分不创造信息，但能改善"和预训练权重的域匹配"〔存疑，效果依场景〕。
4. **损失**：NWD（把框建模成高斯分布，对小目标的位置误差更宽容）。

## Q103. 检测模型压缩：蒸馏、剪枝、量化怎么组合？★★☆

**参考答案**

**三条路线的本质区别**：

```text
蒸馏：大模型 → 小模型（换结构，要重训）
剪枝：大模型 → 稀疏的大模型（结构不变，通道变少，通常要微调）
量化：fp32 → int8（结构完全不变，只换数值表示）
```

**在检测任务上的特殊难点**：

1. **蒸馏的"哪里蒸"很关键**：分类只蒸 logits 就行；检测要蒸 **backbone 特征 + neck 的 FPN 特征 + head 的预测**。论文里常用"特征蒸馏 + 预测蒸馏"组合（如 LD、GID）。
2. **正负样本不平衡让蒸馏更难**：背景占绝大多数，逐像素蒸背景没意义 → 常用**只蒸正样本区域**或按权重蒸。
3. **剪枝会破坏结构耦合**：检测的 neck（FPN/PAN）有跨层连接，剪了通道要保证**各层通道数对齐**；head 的回归分支比分类分支更敏感（**别剪回归头**）。
4. **量化对回归头最敏感**：框坐标是连续值、要求精度；分类是 argmax，对量化宽容。**常见做法：backbone/neck INT8，回归头保 fp16**。

**推荐的组合顺序**（有实践经验的说法）：

```text
① 先量化（收益/成本最高）：PTQ + 校准集，验证业务指标
② 再蒸馏（如果还要更快）：用大模型（或同模型 EMA/更大分辨率）当 teacher
③ 最后剪枝（最麻烦）：结构化剪枝（整通道），微调恢复
```

**为什么这个顺序**：量化几乎不改结构、工具链成熟、可回滚；剪枝改结构、影响所有下游、且要重训——**先做便宜的**。

**追问**：*量化后 mAP 只掉 0.3%，能上线吗？* 不能只看 mAP（Q98）——要看**漏检率**和**小目标召回**。回归头量化误差会让框整体偏移 1–2 像素，mAP 几乎不变但测量类任务已经不可用。
