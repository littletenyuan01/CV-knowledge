## 怎么用

- **时间紧**（面试前 1 小时）：只看每份文件的**附录 A 一页速查表**，那是所有题的一句话答案。
- **系统复习**（一周）：按专题顺序读，**重点看"坑"和"追问"**——面试的区分度都在这两栏。
- **针对性补**：每个专题开头有题量分布表，按块挑。

## 两条阅读约定

1. 标 **〔实现相关〕** 的结论是编译器/解释器/框架实现事实（如 GCC vector 扩容 2 倍、Python 小整数缓存 -5~256），标准未规定——答的时候**带上这半句限定词**，面试官往往就在考这个。
2. 标 **〔版本相关〕** 的结论指特定版本的行为（如 `torch.cuda.amp` 在 2.4 起为旧接口），回答时说明版本；标 **〔存疑/有争议〕** 的说明业界结论不一致，说明这点本身就是加分项。

## 转换成 Word

管线在仓库根目录 `tools/`：`md2docx.py` 负责 Markdown → docx，`run_docx_pipeline.py` 是"重建 + 结构检查 + 转 PDF + 越界校验"的外壳。

**注意（已核对源码）**：这两个脚本的输入输出路径是**写死的常量**，不是命令行参数——`md2docx.py` 里 `SRC`/`OUT` 指向 `图像处理面试150题.md/.docx`，`run_docx_pipeline.py` 同样固定该文件。要转换本目录的专题文档，需要先改这两个常量，再运行：

```bash
python tools/md2docx.py
```

管线支持标题 / 表格 / 围栏代码 / 引用，**不支持图片**——所以本文档的图都用 ASCII 画在代码块里，转 Word 后是等宽灰底块，不会丢。
