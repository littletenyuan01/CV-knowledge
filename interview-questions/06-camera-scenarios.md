## 答题模板（所有场景题都套这个）

面试官要听的不是「我会用双边滤波」，而是下面这五步。先讲框架再加细节，分数差一个档。

1. **定位链路**：光学/传感器 → ISP → 编码 → 显示/后期。先问三句：**是所有设备都这样，还是单机？是预览、成片还是导出？有原图/RAW 吗？**
2. **量化现状**：把「看着不对」变成数字——ΔE2000、平坦区噪声 σ、边缘宽度（MTF）、直方图两端与中位数、块效应能量。
3. **最小改动**：先改参数（锁 AWB/AE、关锐化、换 gamma 档）→ 再改算法 → 最后才谈硬件。改动越小，回归面越小。
4. **修复**：优先在「信息还没丢」的域做（RAW > 线性 > 感知域），顺序错了后面补不回来。
5. **验收 + 回归**：固定一组图（色卡、灰卡、分辨率板、肤色、逆光、夜景），改前改后跑同一套指标。

> 一句话版本：**先分清是「拍错了」还是「显示错了」，再决定在哪一段动手。**

# A. 手机 / 消费电子相机

## S01. 预览里肤色发绿，拍出来却正常 ★★★

**场景**：样机对着人脸，**预览**肤色发绿；按下快门后的**成片**正常。

**怎么办**：三段法定位，别急着改 CCM。

1. 抓 ISP 输出 dump（YUV），看**这一帧本身**是否偏绿。
2. YUV 正常 → 问题在**显示链路**：YUV→RGB 的系数（BT.601 / BT.709 混用）、range（16–235 当 full 用）、或 GPU shader 里通道顺序错。用一张纯灰图 + 红/绿/蓝块就能一眼看出来。
3. YUV 就偏 → 预览与拍照走了**两套 tuning / 两套 3A**：预览档常用更省电的 AWB（或直接沿用拍照档的固定增益）。

**为什么**：手机里预览和拍照经常是两条通路（不同分辨率、不同 ISP 档位、不同 3A 收敛速度），「预览不对、成片对」几乎一定是通路差异，而不是成像本身错。

**追问**：怎么快速区分「601/709 用错」和「增益偏」？—— 用色卡算 ΔE：所有颜色**同向**偏移更像增益/白平衡；只有中间调或饱和色偏，更像矩阵或 gamma。

**坑**：直接改 CCM 去压绿色——成片会跟着坏，而且下次换光源又偏。

## S02. 夜景人像「蜡像感」：噪点少了，细节也没了 ★★★

**场景**：手机夜景模式拍人像，脸很干净但像塑料，头发成块状。

**怎么办**：先分清是**噪声**还是**降噪过度**。

1. 看 RAW 或高 ISO 单帧：若单帧纹理正常，说明是多帧合成/时域降噪吃掉了细节。
2. 检查多帧对齐：手持抖动时局部配准失败的区域会被当成「运动」丢弃 → 这些区域退化成空域强降噪，正好是头发、边缘。
3. 处理：缩短单帧曝光换更多帧数、提高 ISO 上限、降低时域降噪强度；必须用成片时，用**保边滤波 + 高频回贴**（见 S17），不要上 NLM 硬磨。

**为什么**：时域降噪的收益建立在「多帧同一场景」上，一旦对齐失败就只能空域补，细节必然丢。

**追问**：怎么判断是「多帧鬼影」而不是单纯模糊？—— 找双轮廓/重影边缘；鬼影的位置在不同帧之间会跳。

**坑**：用锐化把细节「找回来」，只是把噪声和振铃一起放大。

## S03. 拍屏幕出现彩色摩尔纹 ★★☆

**场景**：拍笔记本屏幕，画面上一圈圈彩色波纹，换角度会变。

**怎么办**：这是**采样混叠**，不是噪声也不是脏。

1. 现场：改变距离/角度、轻微离焦（牺牲一点锐度换掉纹路）、换更长焦段或更高分辨率。
2. 后期：频域陷波（`cv2.dft` + 手工掩模）能压但**必然连带损失细节**；更稳的是多帧不同相位平均（手持微抖本身就是抖动采样）。
3. 不要用中值/高斯「磨平」——纹路会变成一片糊，更难看。

**为什么**：屏幕像素栅格与 sensor 采样率拍频；彩色纹来自 CFA 三个通道的采样率不同。

**追问**：为什么预览时纹路会「流动」？—— 缩放/rolling shutter 让采样相位逐帧变化。

**坑**：把摩尔纹当「噪点」去降噪，越降越糊。

## S04. 拍文档中间清楚、四角发虚 ★★☆

**场景**：A4 合同拍摄，中间字清，四个角发虚、发暗。

**怎么办**：

1. 先判断是**景深/场曲**（合焦面弯曲）还是**边缘 MTF 下降 + 暗角**导致对比不足。拍一张纯文字图，放大看四角是否「糊」而不是「暗」。
2. 几何：四点 `cv2.getPerspectiveTransform` + `warpPerspective` 做透视校正。
3. 光照：用大核模糊估计背景再做 `cv2.divide`，或 `cv2.adaptiveThreshold`（blockSize 取笔画宽度的 2–3 倍、奇数）。
4. 锐化只对**边缘区域**温和做，限制 overshoot。

**为什么**：镜头场曲 + 边缘 MTF 下降，是光学问题；全局拉锐化只会让中间过冲。

**追问**：`adaptiveThreshold` 的 blockSize 怎么选？—— 必须 **odd**，且大于笔画宽度 2–3 倍；太小会把笔画抠断，太大会保留阴影。

**坑**：全局 Otsu → 光照不均时半边文档直接变黑。

## S05. 地下车库扫码，半天扫不出来 ★★★

**场景**：低光 + 手持，二维码在取景框里但一直识别失败。

**怎么办**：先分清是**对不上焦**、**曝光不足**还是**运动模糊**。

1. 对焦：锁 AE 后看画面是否清楚；开 PDAF/激光辅助；限制 ROI 到取景框中央（减少误对焦）。
2. 曝光：手动缩短曝光时间（压运动模糊）→ 提增益 → 噪声上升，取平衡；必要时多帧不同曝光尝试。
3. 解码：局部二值化而非全局；`cv2.QRCodeDetector` / `wechat_qrcode` 对模糊更鲁棒，但输入仍要够锐。

**为什么**：二维码解码依赖模块边界的锐度，运动模糊直接抹掉边界。

**追问**：为什么「提高分辨率」不一定更好？—— 像素变小、单像素进光量下降，暗光噪声反而更重。

**坑**：一味拉 ISO → 噪声淹没模块，解码率更低。

## S06. 连拍十张，从第四张开始偏黄 ★★☆

**场景**：连拍交付客户，前几张正常，后面整组偏黄。

**怎么办**：

1. 判断是 AWB 场景切换检测过敏 + 增益未限速（主体移动导致单帧统计突变）。
2. ISP 侧：对 AWB 增益做时域低通（每帧限幅 5%–10%）、加时间滞回、用连续多帧统计；拍摄前直接 **AE/AWB Lock**。
3. 后期：以第一张为参考，对整组做增益对齐（先对齐灰卡或中性区域）。

**为什么**：AWB 是闭环，单帧统计在主体变化时会把「画面变黄」误判为「光源变黄」。

**追问**：为什么商用交付必须锁白平衡？—— 逐张自动 AWB 会让同一组图颜色不一致，客户拼版时立刻看出来。

**坑**：只修最后几张，整组色调不统一。

## S07. 摇镜时竖直物体是斜的（果冻效应） ★★☆

**场景**：视频摇镜，柱子、门框明显倾斜；快速横移时更严重。

**怎么办**：这是**卷帘快门**（逐行曝光）。

1. 拍摄端：缩短单帧曝光（提高快门角）、降低摇镜速度、开电子防抖时注意裁切。
2. 硬件：换全局快门（工业相机常见，手机基本没有）。
3. 后期：按行做位移校正，需要估计行间时间差与运动速度；只能近似，运动复杂时修不干净。

**为什么**：每行曝光时刻不同，行读出时间 × 运动速度 = 行间位移。

**追问**：为什么闪光灯拍摄会出现横条？—— 光源闪烁（50/60 Hz）与逐行曝光不同步，anti-flicker 就是把曝光时间量化到半周期整数倍。

**坑**：用「整帧平移」去修卷帘——每行位移不同，修不了。

## S08. 广角切主摄，颜色和亮度「跳一下」 ★★★

**场景**：变焦到 1×/2× 切换瞬间，白平衡和亮度明显跳变。

**怎么办**：

1. 多摄标定：每颗模组各自的 AWB 增益、CCM、LSC、相对照度。
2. 切换时做**过渡**：按 zoom 比例混合两路的增益与 CCM，持续 200–300 ms，而不是硬切。
3. 统一 AE 目标（同一目标亮度），避免切换瞬间整体变亮/变暗。

**为什么**：不同模组的光谱响应、镜头透过率、LSC 都不同，同一场景下各自收敛到不同的白点。

**追问**：怎么评估一致性？—— 同一场景双摄同时拍，算色卡 ΔE00、灰卡 RGB 比、亮度差；这是可交付的验收指标。

**坑**：只对齐亮度不对齐色温 → 切换时「闪一下黄」。

## S09. 逆光人像：脸黑、背景过曝 ★★★

**场景**：窗户前拍人，脸欠曝，窗外一片白。

**怎么办**：

1. 拍摄端：AE 用人脸/ROI 加权测光，或 HDR 多曝光合成（参考实现 `cv2.createMergeMertens`）。
2. 后期：阴影提亮要用**保边**方式（局部 tone mapping），并限制半径，避免光晕。
3. 算法侧：能拿 RAW 就拿 RAW，在 log 域或线性域做，别在 sRGB 码值上硬拉。

**为什么**：全局 AE 会被高光区拉低；gamma 提亮会把暗部噪声一起放大。

**追问**：为什么不直接拉曲线？—— 高光已经裁切，拉不回来；暗部噪声会被放大成彩色噪点。

**坑**：局部 tone mapping 参数过大 → 人物边缘出现光晕（halo）。

## S10. 近距离闪光灯：脸惨白、背景死黑 ★★☆

**场景**：室内开闪光拍人，前景过曝，背景几乎全黑，肤色还发白。

**怎么办**：

1. 曝光：预闪测距，按距离调闪光输出（GN/d 的关系）；必要时提高 ISO 保背景。
2. 白平衡：闪光色温（约 5500 K）与环境光不同，混合光源下全局 AWB 必然错一边；用闪光白平衡档或分区域估计。
3. 后期：前景（闪光主导）与背景分开处理，分别校正。

**为什么**：闪光强度按 1/d² 衰减，前景与背景是两个「光源环境」。

**追问**：为什么闪光下肤色容易偏？—— 闪光光谱 + 皮肤次表面散射 + 高光饱和，三者叠加。

**坑**：用全局 AWB 修正前景，背景偏得更厉害。

## S11. 白墙/天空出现一圈圈色带 ★★☆

**场景**：拍白墙，渐变区域出现明显台阶（banding）。

**怎么办**：

1. 判断是**量化位深不足**还是**曲线拉太狠**：看内部处理位深与输出位深；8 bit 输出 + 强曲线最容易出。
2. 修复：输出前加**抖动**（dither，蓝噪声 ±0.5 LSB 量级）、内部保持 10/12 bit 处理、避免过度拉曲线。
3. 视频里更严重（4:2:0 + 压缩），需要在编码前处理。

**为什么**：平滑渐变被量化成台阶，人眼对平坦区的台阶极其敏感。

**追问**：为什么加高斯噪声不行？—— 噪声要「高频、低幅、无偏」，否则会出现可见颗粒或整体发灰。

**坑**：用锐化/对比度「掩盖」banding，反而把台阶强化。

## S12. 拍小孩跑步，人物糊成一片 ★★☆

**场景**：室内运动抓拍，快门慢，人物拖影。

**怎么办**：

1. 提快门（缩短曝光）→ 提增益/ISO → 噪声上升，这是必然权衡。
2. 用运动预测/多帧融合；连拍里挑最锐的一帧。
3. 后期去模糊（Wiener / Richardson-Lucy）只在 **PSF 已知 + 信噪比高** 时有效，否则振铃比模糊更难看。

**为什么**：曝光时间内物体移动超过 1–2 px 就会糊。

**追问**：怎么估 PSF？—— 找画面里的高光点，看它的拖影长度与方向。

**坑**：盲目反卷积 → 边缘出现振铃，评审一眼看出「修过」。

## S13. 家里白墙拍证件照，背景发灰 ★★☆

**场景**：手机拍证件照，背景不是纯白，还有轻微偏色。

**怎么办**：

1. 先白平衡（灰卡或白纸），再做**局部**曝光归一（只作用于背景区域）。
2. 抠图后填充纯白，边缘做抗锯齿；不要直接全局阈值。
3. 按证件照规格裁切、输出（尺寸/DPI/背景色值）。

**为什么**：白墙反射率不是 100%，且受环境光色温影响；全局拉曲线会让人脸过曝。

**追问**：为什么阈值抠图边缘会有白边？—— 边缘像素是前景与背景的混合，直接二值化会保留一半背景色。

**坑**：为了背景白而拉高曝光，人脸细节全丢。

## S14. 数码变焦放大后「糊成油画」 ★★☆

**场景**：没有长焦，2× 纯裁切放大，细节全无。

**怎么办**：

1. 能用光学变焦/多摄融合就用。
2. 多帧超分：手持微抖提供亚像素位移，多帧配准 + 融合能真提升分辨率（不是插值）。
3. ISP/后期：边缘导向插值（如 `cv2.resize` 的 `INTER_CUBIC` 只是起步），轻量超分网络更有效。

**为什么**：裁切后有效分辨率下降，插值不能创造信息；多帧能，因为多了采样。

**追问**：为什么单帧超分容易「假」？—— 网络在补高频，补出来的不一定是真实纹理。

**坑**：用锐化掩盖插值模糊 → 锯齿 + 振铃。

# B. 修图 / 设计 / 电商

## S15. 白底图边缘一圈灰 ★★★

**场景**：电商产品抠图换纯白底，产品边缘有灰边。

**怎么办**：

1. 先确认不是抠图不准，而是**边缘混色**（前景与旧背景的线性混合）。
2. 颜色去污（decontamination）：已知背景色 B 与 alpha，反解前景 F = (I − (1−α)B)/α，再合成到新底。
3. 或者对边缘做 1–2 px 收缩 + 抗锯齿（简单但会掉细节）。

**为什么**：抗锯齿边缘本来就是「部分前景 + 部分背景」。

**追问**：为什么直接羽化不行？—— 羽化只是把灰边变宽变柔，白底上仍然是一圈灰。

**坑**：只调阈值，边缘在深色产品上会留白边、浅色产品上留灰边。

## S16. 换背景后头发像剪纸 ★★☆

**场景**：人像换背景，发丝边缘生硬、丢失。

**怎么办**：

1. 做 **trimap**（确定前景 / 确定背景 / 未知带），未知带覆盖发丝区域。
2. 用 alpha matting：closed-form、guided filter matting、KNN matting 都可以；在高分辨率上算 alpha 再下采样。
3. 合成时用 alpha 混合，并对边缘做轻微颜色去污。

**为什么**：硬分割只能给 0/1 的 alpha，而发丝是半透明的。

**追问**：`guided filter` 的半径和 eps 怎么影响结果？—— 半径大、eps 大 → alpha 更平滑但边缘更糊；eps 小 → 保留细节但容易把背景纹理带进来。

**坑**：trimap 未知带太窄 → 发丝被切掉；太宽 → 背景色渗入。

## S17. 磨皮磨成「塑料脸」 ★★★

**场景**：一键美颜后皮肤没有毛孔、没有光影层次。

**怎么办**：**频率分离**。

1. 低频 = 保边滤波（双边 / 导向滤波 / 表面模糊）→ 只平滑肤色与光影，不动边缘。
2. 高频 = 原图 − 低频 → 按蒙版把纹理「贴回去」，强度可控。
3. 用皮肤检测（YCbCr/HSV 阈值 + 形态学）生成蒙版，限制作用区域；五官边缘保护。

**为什么**：把高频整体压掉，皮肤就失去质感；完全不压，瑕疵还在。

**追问**：双边滤波 O(d²) 太慢怎么办？—— 导向滤波 / 快速双边 / 表面模糊，O(N) 量级。

**坑**：全图磨皮 → 背景、衣服纹理一起被抹平。

---

## S18. 一批 50 张产品图，色温各不相同 ★★★

**场景**：电商上新，同一批货拍出来每张白平衡都不一样，拼在一起很明显。

**怎么办**：

1. 拍摄端：固定光源 + 灰卡 + **锁死 AWB/AE**（这是成本最低、效果最好的一步）。
2. 后期：以灰卡（或第一张）为参考，做增益对齐；需要更精细就在 **Lab** 空间对齐 a/b（色度），L 单独处理。
3. 要求高就做色卡标定 + CCM，批量套同一组参数。

**为什么**：自动 AWB 逐张决策，场景里产品颜色一变，白点就跟着变。

**追问**：为什么在 Lab 里对齐比 RGB 好？—— 亮度与色度解耦，调色不会连带改变明暗。

**坑**：直接对 RGB 三通道做直方图匹配 → 产品颜色被「拉」成参考图的颜色。

## S19. 设计稿在自己屏幕上高级，客户手机上看偏黄 ★★☆

**场景**：设计师用广色域屏，客户在手机上看，颜色明显不同。

**怎么办**：

1. 先确认源文件是否嵌入 ICC（sRGB / Display P3），以及设计软件的色彩管理设置。
2. 软打样：把目标空间设为客户设备（sRGB），看差异。
3. 交付：统一转 sRGB 并嵌入 profile；超出色域的颜色要接受裁剪，或用感知意图压缩。

**为什么**：同一组 RGB 数值在不同色彩空间里代表不同颜色，缺 profile 就只能靠猜。

**追问**：P3 → sRGB 转换要注意什么？—— 超出 sRGB 的颜色会被裁切，红/绿最明显；用相对色度意图 + 黑场补偿更稳。

**坑**：直接截图交付（截图常带系统色彩配置或已转 sRGB），数值和设计稿对不上。

## S20. 要做「青橙」电影色调 ★★☆

**场景**：海报需要暗部偏青、高光偏橙的风格，但不想把肤色做脏。

**怎么办**：

1. 不要直接拉 RGB 单通道曲线（会同时改亮度与饱和）。
2. 用**色相分离**：在 Lab/LCh 或 HSL 里，把暗部推向青、高光推向橙；再用蒙版保护肤色。
3. 固化成 3D LUT（网格采样 + 三线性插值），保证批量一致。

**为什么**：RGB 曲线是「按亮度」改，色相分离是「按色相/明度」改，后者可控得多。

**追问**：3D LUT 怎么落地？—— 采样 N³ 网格，对每个格点做目标变换，插值应用；注意 LUT 是设备/空间相关的。

**坑**：全局加青 → 肤色发灰、白衣服变冷，评审一眼假。

## S21. 老照片修复：发黄、噪点、划痕 ★★☆

**场景**：扫描的老照片，整体发黄、颗粒重、有折痕划痕。

**怎么办**（顺序很重要）：

1. 白平衡/褪色校正（灰点或直方图对齐）。
2. 去噪：NLM/BM3D，控制强度避免抹掉纹理。
3. 划痕检测（形态学 + 局部异常）→ `cv2.inpaint`（Telea / NS）。
4. 最后轻微锐化。

**为什么**：顺序反了会把划痕当细节强化，或者去噪后划痕更难检测。

**追问**：为什么先校色再去噪？—— 色偏会影响噪声估计与阈值，先归一化统计量更稳。

**坑**：过度 inpaint 把布料纹理、皮肤纹理一起抹平。

## S22. 合成后人物「飘」在新背景上 ★★☆

**场景**：人像换背景，脚下没有影子，像贴上去的。

**怎么办**：

1. 保留原图的阴影，或按主光方向重建：阴影层 = 环境遮挡（乘性），用 multiply 混合。
2. 接触阴影（contact shadow）沿脚底/接触线做高斯衰减，越靠近越深。
3. 注意色温：新背景是冷光，阴影也要偏冷。

**为什么**：阴影是「光被挡住」，是乘法关系，不是加一块黑。

**追问**：为什么直接用黑色画笔涂会假？—— 黑色会降低饱和度且边缘过硬，真实阴影是柔和的乘性衰减。

**坑**：阴影方向与主光不一致，比没有阴影更假。

## S23. 屏幕上鲜艳，印出来发闷 ★★☆

**场景**：海报设计稿在屏幕上很亮，印厂打样偏暗偏灰。

**怎么办**：

1. 走软打样：用印厂的 ICC profile 预览，接受色域更小的事实。
2. 转换意图选感知/相对色度，开黑场补偿（BPC）。
3. 关键色（品牌色、肤色）单独打样确认；必要时用专色。

**为什么**：CMYK 是减色、色域比 RGB 小，超出的颜色只能被压缩。

**追问**：为什么大面积黑要用 K 而不是 CMY 叠？—— 油墨总量限制、套印偏差、干燥问题。

**坑**：无 profile 直接 RGB→CMYK，黑场发灰、暗部并阶。

## S24. 证件照换底色，边缘一圈蓝 ★★☆

**场景**：蓝底照片换白底，人物边缘有一圈蓝边。

**怎么办**：

1. 色度键：在 HSV 或 YCrCb 里按色相/色度阈值分割背景，比 RGB 稳。
2. 边缘处理：收缩 1–2 px + alpha 羽化 + 颜色去污（同 S15）。
3. 头发区域用 matting 兜底。

**为什么**：抗锯齿边缘像素混合了旧底色，直接替换会留下旧色。

**追问**：为什么 HSV 比 RGB 好？—— 色相与亮度解耦，光照变化时阈值更稳。

**坑**：阈值太松 → 蓝色衣服和背景一起被抠掉。

# C. 跨域通用

## S25. 客户给的一张 JPEG，有块效应和过锐化光环 ★★☆

**场景**：只给了一张压缩过的图，要求「修好」。

**怎么办**：

1. 先诊断：8×8 块边界能量（判断压缩程度）、边缘两侧的过冲（判断是否被锐化过）。
2. 去块：轻量 deblocking / 低强度 NLM；**不要再锐化**。
3. 若要做测量或印刷，明确告知「信息已损失，建议提供原图/RAW」。

**为什么**：过锐化的 overshoot 会破坏亚像素定位与边缘测量，越修越偏。

**追问**：怎么检测过锐化？—— 看边缘两侧是否出现「亮边+暗边」的过冲，统计过冲幅度分布。

**坑**：用锐化去「补」模糊，伪影叠加。

## S26. 图整体发闷，但直方图两端没截断 ★★☆

**场景**：照片不黑不白，就是「灰蒙蒙」。

**怎么办**：区分**曝光不足**与**对比度不足**。

1. 看中位数与动态范围：整体偏移 → 曝光/黑点问题；分布集中在中间 → 对比问题。
2. 曝光类：调黑点/白点、提曝光；对比类：S 曲线或 CLAHE（局部，注意噪声放大）。
3. 判断依据是「信息还在不在」——两端没截断说明还能救。

**为什么**：两种问题的处理方向相反，混着调就顾此失彼。

**追问**：CLAHE 的 `clipLimit` 与 `tileGridSize` 怎么选？—— tile 越小局部越强、越容易出块；clipLimit 越大对比越强、噪声越明显。

**坑**：全局拉对比 → 高光爆、暗部噪点炸出来。

## S27. 客户说「画质不清楚」，怎么量化 ★★★

**场景**：一句主观反馈，需要给结论和整改方向。

**怎么办**：拆成四个可测量的维度：

1. **分辨率**：边缘扩散函数/MTF50、或直接量边缘过渡宽度（像素数）。
2. **噪声**：平坦区标准差（分亮度段统计）。
3. **对比度**：局部 RMS 对比度。
4. **伪影**：块效应强度、振铃、过冲。

同一组测试图（分辨率板、灰卡、色卡、夜景）改前改后对比。

**为什么**：「不清楚」可能是模糊、噪声、低对比、过锐化中的任意一种，处理方式完全不同。

**追问**：为什么 PSNR 高也可能看着糊？—— PSNR 对模糊不敏感，对噪声敏感；模糊图 PSNR 可能很高但主观很差。

**坑**：直接上锐化，把「不清楚」变成「锐但脏」。

## S28. 两台设备拍同一场景，颜色对不上 ★★☆

**场景**：手机 A 与 B 拍同一张色卡，肉眼可见色差。

**怎么办**：

1. 排除变量：锁 AE/AWB、同光源、同曝光。
2. 分层比较：灰卡 RGB 比（白平衡）→ 色卡 ΔE00（CCM）→ 灰阶（gamma/色调曲线）。
3. 对齐：以 A 为参考，给 B 求一个 CCM（最小二乘 + 行和约束），或两者都对齐到 sRGB。
4. 出报告：逐色块 ΔE00，明确「可接受范围」。

**为什么**：不同 sensor 光谱响应 + 不同 tuning，差异是系统性的，可以标定。

**追问**：ΔE00 多少算「看不出来」？—— 一般 ΔE00 < 2 肉眼较难分辨；工业/电商可要求更严（< 1），需按场景约定。

**坑**：只匹配亮度，颜色仍然不对；或者用单张图求 CCM，过拟合。
