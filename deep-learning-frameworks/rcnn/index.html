R-CNN 逐步详解

本页只讲 R-CNN 一个模型，但把每一步的输入、输出、张量尺寸、超参数、公式与耗时全部写清楚。 读完之后你应该能做到：不看代码就完整复述一遍推理流程；能解释每个超参数为什么取那个值； 能手推一次 IoU、NMS、边框回归的编码与解码。

01R-CNN 到底做了什么

一句话：先在图上猜出约 2000 个「可能有东西」的框，再把每个框抠出来缩成 227×227 送进 CNN， 用 CNN 特征让 SVM 判断类别、让回归器修正位置，最后用 NMS 去掉重复框。 整个模型没有端到端训练，是三个独立模块串起来的。

1.1 完整流程的输入输出规格（先建立全局印象）

步骤输入输出关键参数
① 候选区域RGB 图像，任意尺寸（论文短边缩放到 500 或 600）约 2000 个 (x, y, w, h)，与类别无关按分数排序截断 K=2000
② 区域归一化原图 + 单个候选框3×227×227 的 patch各向异性缩放，外围补 p=16 像素均值
③ CNN 前向3×227×227pool5（6×6×256 = 9216 维）、fc7（4096 维）AlexNet 权重（ImageNet 预训练 + 域内微调）
④ SVM 打分fc7，4096 维21 个分数（20 类 + 背景）每类一个线性 SVM，C 用验证集调
⑤ 边框回归pool5，9216 维每类 4 个偏移量 (dx, dy, dw, dh)岭回归，λ=1000，只用 IoU≥0.6 的样本
⑥ NMS所有框 + 分数最终检测框类内贪心，IoU 阈值 0.3
为什么值得一步步抠细节

因为 R-CNN 的所有后续改进都精确对应这里的某一处缺陷： 第 ③ 步重复计算 → Fast R-CNN 的 RoI Pooling； 第 ④⑤ 步割裂 → 多任务联合损失； 第 ① 步不可学习 → Faster R-CNN 的 RPN。 把每一步看透，后面三代模型的每个设计都会变得理所当然。

02第 1 步 · 候选区域生成（Selective Search）

这一步的任务：不看类别，在图上找出约 2000 个「可能有物体」的框，并保证几乎不漏物体。 它没有任何可学习参数，纯 CPU 算法，论文用的是 Uijlings 等人 2013 年的 Selective Search。

2.1 算法细节：从超像素到候选框

  1. 初始过分割：用 Felzenszwalb & Huttenlocher 的图分割算法（基于图论的高效分割）把图像切成大量小区域， 通常得到 1000~2000 个超像素块。这一步只依赖像素颜色相似度与边缘，不涉及语义。
  2. 为每个区域计算特征描述子：
    • 颜色：对每个颜色通道取 25 个 bin 的直方图，得到 75 维（RGB 三通道）；
    • 纹理：用类 SIFT 的梯度方向直方图，8 个方向 × 10 个 bin = 80 维。
  3. 计算相邻区域对的四种相似度：
    • s_color：颜色直方图的交集（sum of min），越大越相似；
    • s_texture：纹理直方图的交集；
    • s_size：鼓励合并小区域。定义为 1 − (size(ri) + size(rj)) / size(im)， 即两个区域越小，这一项越接近 1；作用是防止某个大区域不断吞并周围一切；
    • s_fill：填充度。衡量合并后的区域与它的外接矩形有多贴合： 1 − (size(BBij) − size(ri) − size(rj)) / size(im)。越能「填满」外接框，合并越被鼓励。
  4. 加权求和成单一相似度并贪心合并：
    s(ri, rj) = a1·scolor + a2·stexture + a3·ssize + a4·sfill 式 2-1
    其中 a1..4 ∈ {0, 1}。每轮把相似度最高的一对合并，并更新它与邻居的相似度（用高效的数据结构维护）。
  5. 记录合并轨迹：合并过程中产生的每一个区域都作为候选框输出。 然后按多样性策略取并集——例如在多种颜色空间（RGB、HSV、Lab 等）下、 用不同的 a 组合（论文跑了 80 种配置）分别执行，最后排序截断。 这样做的目的是让候选集合覆盖尽可能多的「可能物体」形态，而不是只偏向某一种相似度定义。
  6. 截断：把所有候选框按启发式分数排序，测试时取前 K ≈ 2000 个。 注意训练和测试可以取不同的 K（论文中训练和测试都常用 2000）。
交互演示 1 · 候选框数量 ↔ 召回率的权衡

这一步决定了整条链路的性能上限。拖动滑块：K 太小 → 物体完全没有候选框覆盖（阶段一漏检，后面救不回来）； IoU 阈值越高 → 越难达到，因为候选框来自区域合并、天然不够精确。

三个容易踩的细节

① 候选框不是物体框：大量候选是背景、物体的一部分或几个物体的拼接。后面 SVM 的负样本正是从这里挖出来的。

② 训练时必须把真值框也塞进候选集合（并给最高分），否则某些物体可能没有足够好的候选框作为正样本。

③ K 是一个需要调的参数：K 太小伤召回，K 太大则 ③ 步耗时线性增长（因为每个候选都要跑一次 CNN）。 这个「召回 vs 计算量」的矛盾，正是 Faster R-CNN 用 RPN 替代它的动机之一。

03第 2 步 · 区域归一化到 227×227

候选框尺寸千奇百怪，而 AlexNet 要求固定输入。这一步要把任意长宽比的区域变成 3×227×227。 看似简单的缩放，藏着两个会影响精度的细节：用什么缩放策略、要不要留上下文。

3.1 三种做法与论文的选择

策略做法优点缺点
各向异性缩放（warp）
论文最终采用		 不管长宽比，直接把候选框内容拉伸成 227×227 实现最简单；所有像素都参与计算，无信息丢弃；缓存时最省空间 破坏物体的形状先验（高瘦的人被压扁）
各向同性缩放（crop） 保持长宽比，把候选框的短边缩放到 227，再用 227×227 的窗口在其中裁剪 保留形状先验，更符合物体真实外观 细长物体会被裁掉一部分（站立的人、公交车）；需要多次尝试不同裁剪位置
各向同性缩放（含上下文） 把候选框向外扩展（例如各方向扩 16 像素）后再保持长宽比缩放 额外补入了物体周围的环境信息，论文中该变体精度略高 上下文宽度需要作为超参调

论文的消融结论：三种做法在 VOC 上 mAP 接近（差距在 1~2 个点内）， 但 warp 最简单、最快、最省缓存，因此被选为默认。 论文同时说明：为了补偿 warp 带来的形状失真，在缩放后的 patch 外围补了 p = 16 像素的均值像素（mean pixel）边框，人为给网络一点上下文。

3.2 精确的数值流程

设候选框在原图上为 (x, y, w, h)，目标尺寸 227×227，上下文 p = 16：

① 扩展候选框：x' = x − p，y' = y − p，w' = w + 2p，h' = h + 2p
② 从均值图上抠出该区域：超出原图边界的部分用均值像素填充（不是黑边，也不是零）
③ 各向异性缩放到 227×227：横向缩放比 sx = 227 / w'，纵向 sy = 227 / h'
④ 通道顺序与均值减法：AlexNet 训练时用的是 BGR 顺序与 ImageNet 均值， 这组预处理必须与预训练时完全一致 区域归一化

这里是复现时最容易出错的地方

预处理不一致导致的精度损失，通常比模型结构写错更严重。务必核对四件事： 通道顺序（原始 Caffe 模型是 BGR）、 均值减法的数值（ImageNet 均值，不是 0.5/0.5）、 缩放时是否做了抗锯齿插值、 p=16 的填充用的是均值像素还是零。 这四项任何一项错了，mAP 可能掉几个点到十几个点。

04第 3 步 · CNN 前向提取 fc7 特征

把 227×227 的 patch 送进在 ImageNet 上预训练、又在检测数据上微调过的 AlexNet， 取倒数第二层全连接（fc7）的 4096 维输出作为该候选框的特征。 整个 R-CNN 的算力几乎都花在这一步。

4.1 AlexNet 逐层规格与参数量

AlexNet 是 2012 年的设计，有几个今天看来不寻常的地方，但复现时不能改： LRN（局部响应归一化）、conv1 的 11×11 大核 stride 4、 pool 是 3×3 stride 2 的重叠池化，以及三个巨大的全连接层。

用预训练网络的倒数第二层当通用特征，是跨任务的稳健选择： 太浅语义不足，太深则过拟合到源任务的类别空间。 这也是今天在 ViT / CLIP 上做检测、检索、度量学习时，特征通常取 neck 之前而非 logits 的原因。

4.3 这一步的代价：为什么占 95% 的时间

2000 个候选框各自独立跑一次完整的 AlexNet 前向。而这些候选框彼此高度重叠 （IoU 常见 0.3~0.6），意味着同一块图像区域的卷积结果被反复计算了几十到上百次。

计算量估算（VGG16 版本，更直观）：
单个 patch 前向 ≈ 15.5 GFLOPs　×　2000 个候选框 ≈ 31 TFLOPs / 图
而如果只对整图做一次卷积（Fast R-CNN 的做法），同分辨率下约 0.2 TFLOPs
→ 冗余倍数约 100+ 倍，这就是 Fast R-CNN 能提速 200 倍左右的根本原因

补充：R-CNN 的 SVM 与回归器共用这套特征，所以训练时特征只需抽取一次并缓存—— 但这也带来了数百 GB 的磁盘写入与读取（见第 7 节）。

05第 4 步 · 逐类线性 SVM 打分

每个候选框得到一个 4096 维 fc7 之后，用 21 个独立的线性二分类 SVM （VOC 20 个类别 + 1 个背景）分别打分，取分数最高的类别作为预测。 这一步是 R-CNN 最容易被问、也最容易答错的细节。

5.1 为什么不用微调时那个 softmax

作者把 CNN 微调好了，却不用它的 softmax 输出，而是把特征抽出来单独训 SVM。原因在正负样本的定义不同：

微调时的定义（宽松）

与某个真值框的 IoU ≥ 0.5 就视为该类的正样本，IoU < 0.5 视为背景。 一个只覆盖了半个人、或包含大量背景的框，也会被当作 person 的正样本去训练。

→ softmax 学到的是「像 person 的区域」，对定位精度不敏感。

SVM 训练时的定义（严格）

只有真值框本身是正样本，其余全部是负样本，并且配合难例挖掘： 先用初始负样本训练，再专门把误检最严重的负样本加入迭代。

→ 决策边界严格得多，特别擅长压制「背景被判成物体」。

配置（VOC 2007，无边框回归）mAP结论
ImageNet 预训练 → fc7 + SVM（不微调）约 50.9%迁移学习直接可用，但未适应检测域
域内微调后 → fc7 + softmax50.9%把 fc8 换成 21 类联合训练
域内微调后 → fc7 + 逐类 SVM54.2%比 softmax 高约 +3.3 个点
域内微调后 → pool5 + SVM更高论文报告 pool5 特征配 SVM 进一步提升

5.2 线性 SVM 的目标函数与求解

对每个类别 c，单独训练一个线性 SVM，权重为 wc（4097 维，含偏置），优化目标为 L2 正则化的 hinge loss：

minwc　(1/2)‖wc‖² + C · Σi max(0, 1 − yi · (wcT fi))

其中 fi ∈ R4096 是第 i 个候选框的 fc7 特征，yi ∈ {+1, −1} 表示是否属于类别 c， C 是正则强度，用验证集做 grid search 选取 式 5-1

实现上论文用的是 liblinear 这类通用线性分类器求解器。 注意这里是 20 个独立的二分类问题（one-vs-rest），而不是一个 21 类的多分类 softmax—— 所以每个类别的分数之间没有归一化关系，不能当作概率，只能用于排序与阈值。

5.3 难例挖掘（Hard Negative Mining）的完整流程

  1. 初始训练：对类别 c，用全部正样本（真值框）+ 一小批随机负样本训练初始 SVM；
  2. 全量打分：用这个 SVM 对训练集上所有负样本候选框打分；
  3. 挑出难例：把分数最高（即最容易被误判为正样本）的负样本挑出来，这些就是「难负样本」；
  4. 追加重训：把难负样本加入训练集，重新训练 SVM；
  5. 迭代：重复 2~4，论文做了 1~2 轮，并对 C 值做 grid search。
为什么必须做难例挖掘

候选框里绝大多数是背景，其中大部分「一眼就是背景」（天空、墙面）。随机采样得到的负样本太容易， SVM 学不到真正的决策边界。难例挖掘把算力集中到最像物体的背景上。 这个思想后来演化成 OHEM（在线难例挖掘），再进一步被 Focal Loss 用损失加权的方式「软化」—— 后者不需要显式挑选样本，但目标一致：降低易样本对损失的贡献。

5.4 测试时的打分与选取

推理时，每个候选框会被所有 21 个 SVM 都打一遍分。然后：

  • 取分数最高的类别作为该框的类别；
  • 若最高分是「背景」类，或者最高分类别分数低于阈值，则该框被丢弃；
  • 注意：每个框还会被所有类别的回归器都精修一遍（因为回归器也是逐类训练的）， 再按该类分数排序。这是 R-CNN 的一个冗余点，Fast R-CNN 改成「先分类、只回归分数最高那一类」。
历史评价（很重要）

Fast R-CNN 论文明确指出：「用 SVM 而非 softmax 是不必要的」—— 在联合微调的框架下，softmax 的表现已经超过 R-CNN 的 SVM 组合。 所以这段知识的价值不在「照做」，而在于两点： ① 理解正负样本定义如何决定决策边界（今天做数据清洗、调采样策略时直接可用）； ② 理解难例挖掘 → OHEM → Focal Loss 这条思想线索。

06第 5 步 · 边框回归精修

候选框来自区域合并，只能「大概罩住」物体。这一步用一个线性回归器学习 从候选框到真值框的偏移量，在 VOC 2010 上再涨约 3.5 个 mAP。 这是「粗定位 → 细回归」在检测里的第一次落地，也是今天所有 anchor-based 检测器的标配。

6.1 参数化：为什么中心点要归一化、宽高要取 log

记候选框 P = (Px, Py, Pw, Ph)，真值框 G = (Gx, Gy, Gw, Gh)，回归目标 t 定义为：

tx = (Gx − Px) / Pw　　　　ty = (Gy − Py) / Ph
tw = log(Gw / Pw)　　　　　th = log(Gh / Ph) 式 6-1（编码）
  • 中心点除以宽高：把绝对像素偏移变成相对偏移。 这样同样「向右偏 10%」在大框和小框上产生一致的回归目标，一个线性模型就能覆盖所有尺度；
  • 宽高取 log：宽高的变化本质是乘性的（放大 1.5 倍），取 log 后变成加性， 更适合线性回归；同时 log 天然约束了正负范围，数值更稳定；
  • 若不做这两种归一化，回归器需要针对每个尺度单独调参，且对离群值极度敏感。

预测时反解回来（这就是推理阶段真正执行的公式）：

Ĝx = Pw · dx(P) + Px　　　　Ĝy = Ph · dy(P) + Py
Ĝw = Pw · exp(dw(P))　　Ĝh = Ph · exp(dh(P)) 式 6-2（解码）

其中 d★(P) = w★T · φ5(P)，φ5(P) 是 pool5 的 9216 维特征，w★ 是待学的权重。

w★ = argminŵ★ Σi ∈ {x, y, w, h} (t★i − ŵ★T φ5(Pi))² + λ‖ŵ★‖² 式 6-3（岭回归）
细节取值原因
回归器数量每类一个（VOC 20 个，各输出 4 个值）不同类别的形变模式不同（人细长、车扁平）
输入特征pool5，9216 维比 fc7 保留了更多空间信息，回归位置更合适
参与训练的样本仅 IoU ≥ 0.6 的候选框离真值太远的框，偏移量没有回归意义，还会污染拟合
正则化L2，λ = 1000（论文用验证集 grid search）每类可用样本少，强正则防止过拟合
训练目标式 6-1 的四元组—
测试时的应用对每个候选框、每个类别都输出一组 dR-CNN 的冗余点，Fast R-CNN 改为只回归最高分那一类

R-CNN 无边框回归50.2%—
R-CNN + 边框回归53.7%+3.5
这套参数化如何延续到今天

Faster R-CNN（RPN 的 anchor 回归）、SSD、YOLOv2 及之后、RetinaNet 全部沿用 「中心点除以宽高 + 宽高取 log」的编码方式。变化的是损失函数： R-CNN 用 L2 → Fast R-CNN 换成 Smooth L1（对离群点更鲁棒）→ 再后来换成 IoU / GIoU / DIoU / CIoU Loss（直接优化框的重叠度，而不是逐坐标的数值差）。

07训练流程：四个阶段与全部超参数

R-CNN 的训练是四次独立的过程、三次落盘。这一节把每个阶段的学习率、batch 组成、 样本定义、迭代次数全部摊开——这是动手复现时唯一能救命的东西。

7.1 阶段一：ImageNet 有监督预训练

  • 数据：ILSVRC 2012 分类集，1000 类，约 120 万张图；
  • 输入：随机采样 224×224 patch（测试时中心裁剪 + 10-crop 平均）；
  • 优化：SGD，初始学习率 0.01，每 100k 迭代除以 10，共 310k 迭代；
  • 其他：momentum 0.9，weight decay 5e-4，dropout 0.5（fc6 / fc7）。

7.2 阶段二：域内微调（Domain-specific Fine-tuning）

把 1000 类分类网络改造成 21 类（20 类物体 + 背景）的检测网络：

项目设置说明
分类头改造fc8 从 1000 维换成 21 维，随机初始化其余层用预训练权重初始化
输入候选框 warp 到 227×227用全部候选框，不做筛选
正样本与某真值框 IoU ≥ 0.5 → 该类宽松定义，这是与 SVM 阶段的关键差异
负样本与所有真值框 IoU < 0.5 → 背景（第 21 类）—
每个 batch 组成32 个正样本（每类）+ 96 个背景正负比约 1:3；正样本跨类别均匀采样
学习率0.001（预训练的 1/10）数据量远小于 ImageNet，大学习率会灾难性遗忘
迭代次数30k远少于预训练的 310k
收益约 +5 个 mAP论文中最有价值的工程结论之一：域内微调几乎总是值得的
为什么学习率必须降 10 倍

VOC 检测数据约 1 万张图，ImageNet 有 120 万张，差了两个数量级。 沿用大学习率会让网络在几十次迭代内迅速遗忘预训练学到的通用特征 （灾难性遗忘）。「小学习率 + 少迭代」是迁移学习微调的标准配方， 直接适用于今天 fine-tune 大模型与视觉骨干。

7.3 阶段三：抽取特征并训练逐类 SVM

  1. 对训练集每张图的每个候选框，warp 后跑一次前向，取 fc7（4096 维） 写入磁盘；
  2. 正样本：只有真值框本身（实现上把真值框也作为候选加入）；
  3. 负样本：与所有真值框 IoU 较低的候选框（论文用 IoU < 0.5 归为背景类）；
  4. 对每个类别训练一个线性 SVM（式 5-1），并用难例挖掘迭代 1~2 轮；
  5. 用验证集对 C 做 grid search。

7.4 阶段四：训练边框回归器

  • 输入特征：pool5，9216 维（与 SVM 用的 fc7 不同！）；
  • 样本：与对应真值框 IoU ≥ 0.6 的候选框；
  • 目标：式 6-1 的四元组；
  • 求解：岭回归（式 6-3），λ 由验证集 grid search 得到。
交互演示 5 · 这套流程的存储与 I/O 代价

拖动滑块估算中间结果的数据量。R-CNN 的训练速度有一半受限于 I/O 与磁盘， 因为 CNN 和 SVM 是两个进程，中间特征必须落盘再读回。

四次独立过程：① ImageNet 预训练　② 域内微调　③ 抽 fc7 训 SVM　④ 抽 pool5 训回归器。 每一步的产物都要写盘：微调后的模型权重、全部候选框的 fc7 特征、全部候选框的 pool5 特征。

论文提到的特征文件达到数百 GB 量级，训练一轮需要数小时到十几小时。 这也是 Fast R-CNN 论文反复强调的痛点：multi-stage pipeline … features are written to disk。 端到端联合训练不只是优雅问题，更是训练效率问题。

另一个隐藏成本：一旦发现预处理写错了，整个特征缓存必须重抽一遍—— 这是几百 GB 的重新计算。所以第 3 节的预处理细节务必先验证再开抽。

AlexNet 版本约 13 s / 图（候选框 2000、单次前向更快）。 结论非常清晰：95% 的时间花在「对 2000 个高度重叠的框重复做卷积」， 而 Selective Search 只占 3%，SVM 与回归加起来不到 2%。 所以优化方向不是换分类器，而是消除卷积冗余——这正是 Fast R-CNN 的切入点。

09第 6 步 · NMS 与最终输出格式

同一物体周围会有多个候选框都被判为同一类别（分数不同）。NMS 的任务是每个物体只留一个最好的框。 R-CNN 用的是类内贪心 NMS，IoU 阈值 0.3——比你在 YOLO 里习惯的 0.45~0.5 更激进， 因为选择性搜索产生的候选框之间冗余更大。

交互演示 7 · 亲手拖 IoU，再调 NMS 阈值

左侧拖动两个框实时算 IoU；右侧拖动阈值，看 14 个检测框里哪些被抑制。 IoU 的定义很简单，但它在 R-CNN 里出现了五次（见下表），每次的阈值都不同。

IoU 定义交集 / 并集
微调正样本IoU ≥ 0.5
微调负样本IoU < 0.5
回归样本筛选IoU ≥ 0.6
NMS 抑制同类内 IoU > 0.3
VOC mAP 判定IoU ≥ 0.5 算正确

阈值太大 → 同一物体留下多个框（误检多，精度下降）；阈值太小 → 相邻物体被误删（漏检多，召回下降）。

9.1 贪心 NMS 的精确伪代码

# 输入：同一类别的所有候选框 boxes (N,4) xyxy，对应分数 scores (N)，阈值 thr=0.3
def nms(boxes, scores, thr):
    order = scores.argsort()[::-1]        # 1. 按分数从高到低排序
    keep = []
    while order.size > 0:
        i = order[0]
        keep.append(i)                    # 2. 当前分数最高的框一定保留
        if order.size == 1: break
        ious = iou_of(boxes[i], boxes[order[1:]])   # 3. 与剩余所有框算 IoU
        order = order[1:][ious <= thr]              # 4. 只保留 IoU 不超过阈值的
    return keep

# 注意：R-CNN 是"类内"调用，即对每个类别分别执行一次 NMS
#      如果做成"跨类" NMS（所有类别一起做），"人骑着车"这类重叠物体会被误删

9.2 最终输出格式

NMS 之后，每张图输出一个变长列表，每个元素为：

(class_id, score, xmin, ymin, xmax, ymax)
· class_id：0~19 表示 VOC 的 20 类（第 21 个 SVM 输出的「背景」不产生结果）
· score：该类别 SVM 的原始分数（不是概率，因为每类是独立的二分类 SVM，未做归一化）
· 坐标：原图像素坐标（注意回归是在原图坐标系下做的，不是特征图坐标）
· 同一张图可能有多个同类框（不同物体），也可能一个都没有 输出格式
两个容易搞错的点

① 分数不是概率：21 个 SVM 各自独立输出，分数之间没有归一化关系，加起来不等于 1。 所以不能直接当置信度用于业务阈值，通常需要重新做一次归一化（如 Platt scaling）或改用 softmax 版本。

② NMS 前是否要按分数截断：工程实现通常会先把分数低于阈值的框丢掉再做 NMS， 既减少计算量，也避免低分框干扰。这个顺序会影响最终结果，必须与评估脚本保持一致。

9.3 R-CNN 里的 IoU 出现了五次，别混用

用途阈值作用
微调的正样本IoU ≥ 0.5判定候选框属于哪一类（宽松，为了让网络看到更多样本）
微调的负样本IoU < 0.5判定为背景类
SVM 的正样本仅真值框判定边界更严格，这是 SVM 略优于 softmax 的原因
边框回归的样本筛选IoU ≥ 0.6太远的框偏移量无意义，不参与拟合
NMSIoU > 0.3 抑制类内去重
评估（VOC mAP）IoU ≥ 0.5判定检测框是否正确

工业界常用 Soft-NMS 替代贪心 NMS：不直接删除重叠框，而是按 IoU 衰减它的分数 （s ← s·(1−IoU) 或 s·exp(−IoU²/σ)）。在行人检测、细胞检测、货架商品这类密集场景， 换成 Soft-NMS 往往比改网络结构更快见效。

10.3 FAQ（按被问频率排序）

  1. R-CNN 的完整流程？ Selective Search 生成约 2000 个候选框 → 各自扩展 p=16 并 warp 到 227×227 → AlexNet 前向取 fc7 → 21 个线性 SVM 打分 → 20 个回归器逐类精修 → 类内贪心 NMS（IoU 0.3）。
  2. 为什么用 SVM 不用 softmax？ 两者正负样本定义不同：微调用 IoU≥0.5 的宽松定义，SVM 只用真值框且配合难例挖掘，判定边界更严格。 论文实测高约 3.3 个点。但 Fast R-CNN 已证明在联合微调下 softmax 足够好，所以这条是历史细节， 真正要记住的是样本定义如何影响决策边界。
  3. 候选框为什么是 2000 个？ Selective Search 按启发式分数排序后截断。这是一个工程折中： 2000 个能保证约 98% 的召回率（IoU≥0.5），同时把第 3 步的计算量控制在可接受范围。K 是可以调的参数。
  4. 为什么取 fc7 而不是 pool5 或 fc8？ fc7 兼顾语义抽象与通用性。pool5 语义浅但保留空间结构，因此更适合做边框回归的输入； fc8 已过拟合到 ImageNet 的 1000 类判别空间，迁移性明显下降。
  5. 边框回归的输入特征和目标分别是什么？ 输入 pool5（9216 维），目标为式 6-1 的四元组。逐类训练岭回归（λ=1000）， 只用与真值框 IoU ≥ 0.6 的候选框。
  6. 为什么宽高要取 log？ 把乘性缩放变成加性偏移，使一个线性模型能覆盖所有尺度；同时约束取值范围、提升数值稳定性。 中心点则除以候选框的宽高做归一化，同理。
  7. 微调时学习率为什么降 10 倍？ 检测数据量（约 1 万张）比 ImageNet（120 万张）少两个数量级，大学习率会迅速破坏预训练特征 （灾难性遗忘）。这是迁移学习微调的标准配方。
  8. R-CNN 为什么这么慢？ 2000 个高度重叠的候选框各自独立跑一次完整 CNN 前向，卷积特征被重复计算上百倍， 占约 95% 的时间。Selective Search 只占 3%。
  9. 如果只允许你改一处，改哪里？ 改第 3 步：让所有候选框共享一次整图卷积，再用 RoI Pooling 从共享特征图上取各自的特征。 这就是 Fast R-CNN，能把测试时间从几十秒降到约 2 秒。
  10. 这套流程在今天的检测器里还剩什么？ 「粗定位 + 细回归」的编码方式（中心点归一化 + 宽高 log）、 IoU 驱动的样本分配、难例挖掘 → OHEM → Focal Loss 的思想、 以及NMS 本身。变的是特征共享方式与损失函数，不变的是这套问题分解。

11代码实战：把每一步写出来

理解检测器最快的方式是亲手实现里面的每个算子。下面四个函数覆盖了 R-CNN 全部「有计算逻辑」的部分， 加起来不到 80 行，但每一个都对应前文的一个步骤。

11.1 完整流程：从候选框到最终结果

import numpy as np

# ---------- 步骤 ⑤：边框回归的编码与解码 ----------
def encode_bbox(P, G):
    """P, G: (x, y, w, h)。返回式 6-1 的四元组 t = (tx, ty, tw, th)"""
    Px, Py, Pw, Ph = P
    Gx, Gy, Gw, Gh = G
    return np.array([
        (Gx - Px) / Pw,          # 中心点横向偏移，按宽归一化
        (Gy - Py) / Ph,          # 中心点纵向偏移，按高归一化
        np.log(Gw / Pw),         # 宽度取 log 比
        np.log(Gh / Ph),         # 高度取 log 比
    ])

def decode_bbox(P, d):
    """P: (x, y, w, h)，d: (dx, dy, dw, dh)。返回式 6-2 修正后的框"""
    Px, Py, Pw, Ph = P
    dx, dy, dw, dh = d
    return np.array([
        Pw * dx + Px,            # 注意：偏移量要乘回 Pw，而不是加
        Ph * dy + Py,
        Pw * np.exp(dw),         # log 空间的反解是指数
        Ph * np.exp(dh),
    ])

# ---------- 步骤 ⑥：IoU 与贪心 NMS ----------
def iou_matrix(A, B):
    """A: (N,4), B: (M,4)，格式均为 xyxy（左上、右下）"""
    lt = np.maximum(A[:, None, :2], B[None, :, :2])   # 左上取大
    rb = np.minimum(A[:, None, 2:], B[None, :, 2:])   # 右下取小
    wh = np.clip(rb - lt, 0, None)                    # 负值截断为 0
    inter = wh[..., 0] * wh[..., 1]
    area_a = np.prod(A[:, 2:] - A[:, :2], axis=1)
    area_b = np.prod(B[:, 2:] - B[:, :2], axis=1)
    return inter / (area_a[:, None] + area_b[None, :] - inter + 1e-9)

def nms(boxes, scores, thr=0.3):
    """类内贪心 NMS —— R-CNN 用 thr=0.3"""
    order = scores.argsort()[::-1]
    keep = []
    while order.size > 0:
        i = order[0]
        keep.append(i)
        if order.size == 1:
            break
        ious = iou_matrix(boxes[i:i+1], boxes[order[1:]])[0]
        order = order[1:][ious <= thr]     # 超过阈值的一律抑制
    return np.array(keep)

# ---------- 把整条链路串起来 ----------
def rcnn_infer(image, proposal_fn, cnn_fn, svms, regressors,
               K=2000, p=16, nms_thr=0.3):
    proposals = proposal_fn(image)[:K]                 # ① 候选区域

    patches = []
    for b in proposals:
        patch = crop_with_context(image, b, p)         # ② 扩展 p 并补均值像素
        patch = resize_anisotropic(patch, 227, 227)    #    各向异性缩放
        patches.append(normalize(patch))               #    BGR + 均值减法

    feats = cnn_fn(np.stack(patches))                  # ③ 逐框前向，取 fc7 / pool5
    fc7, pool5 = feats['fc7'], feats['pool5']

    scores = np.stack([svm(fc7) for svm in svms], axis=1)   # ④ 21 个 SVM 打分

    results = []
    for c, reg in enumerate(regressors):            # ⑤ 逐类回归 + ⑥ 逐类 NMS
        refined = np.stack([decode_bbox(b, reg(f)) for b, f in zip(proposals, pool5)])
        s = scores[:, c]
        for i in nms(xywh_to_xyxy(refined), s, nms_thr):
            results.append((c, s[i], *refined[i]))
    return results

11.2 用现有框架跑（对照理解）

R-CNN 本身没有维护良好的现代实现，实际工程里用的是它的后代。但你可以用 torchvision 的算子 直接验证本文的每个公式——尤其 roi_align / roi_pool / nms 这三个。 

import torch, torchvision
from torchvision.ops import nms, roi_align, roi_pool, box_iou

# 验证 IoU 与 NMS（对应步骤 ⑥）
boxes  = torch.tensor([[0., 0., 100., 100.], [10., 10., 110., 110.], [200., 200., 300., 300.]])
scores = torch.tensor([0.9, 0.8, 0.7])
print(box_iou(boxes, boxes))              # 自己算的 IoU 应与之一致
print(nms(boxes, scores, 0.3))             # R-CNN 的阈值：0.3

# 验证 RoI Pooling 与 ROIAlign 的差异（这是 Fast/Mask R-CNN 的核心）
feat = torch.randn(1, 256, 32, 32)               # 模拟 stride=16 的特征图
rois = torch.tensor([[0., 10., 20., 210., 220.]])    # 原图坐标 (batch_idx, x1, y1, x2, y2)
a = roi_pool(feat,  rois, output_size=(7, 7), spatial_scale=1/16)   # 两次量化取整
b = roi_align(feat, rois, output_size=(7, 7), spatial_scale=1/16,
              sampling_ratio=2, aligned=True)                      # 双线性插值，无量化
print((a - b).abs().mean())                # 这就是量化误差造成的影响
注意 aligned=True

torchvision 的 roi_align 默认 aligned=False，此时坐标语义与原始论文略有偏差。 Mask R-CNN 的实现使用 aligned=True，会把 RoI 坐标整体平移 −0.5 以避免半像素偏移。 生产代码里忘记这个参数，通常造成 0.5~1 个点的精度损失。
